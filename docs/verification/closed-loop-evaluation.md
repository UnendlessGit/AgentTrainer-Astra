# Saved local practice outcomes

`evaluate.closedLoop` is a real serialized compute job. It loads an immutable checkpoint, uses the same compiled `_PolicyExecution` path as local inference, decodes the policy's packet, and steps `PracticeEnvironment` in virtual time. It never calls the oracle or puts fixture answers into observations. Recurrence resets before each trial; reward shaping is disabled. Pointing and delayed visual memory are the only supported success semantics, and they do not imply general desktop ability.

`ClosedLoopProtocol` freezes the task, cadence/lead, cue/delay/time limit, explicit ordered seeds and pixel/logical layouts, action-selection mode, policy seed schedule and categorical meanings. Greedy trials use key zero and disregard an unused policy seed in protocol comparison. Sampled trial i starts from policy seed + i. The semantic SHA-256 fingerprint includes ordered field/value UUIDs but omits display labels. Model architecture may differ across candidates; task controls, timing and contexts must match. Defaults use a separate seed range, but the interface says **fixed evaluation seeds** and does not claim training disjointness without evidence.

The worker returns per-trial outcomes, success, return, actual decision count and virtual duration. Timeouts, wrong terminal choices and action/numerical faults remain distinct. The native side validates complete trial identity/counts and finite timing/returns before publishing history. Success zero is a completed result; cancellation and failure carry no partial aggregate. These are virtual outcomes, not physical input effects or wall-clock deadline measurements.

Practice history has its own documents/table, preserving existing demonstration-NLL history unchanged. Each attempt is saved before execution, finalized once, and marked interrupted after an unclean restart. Configuration, results and evaluation documents are retained under `Jobs/<evaluation-id>`. Checkpoint comparisons run sequentially and accept only matching complete protocols. The saved-result action can evaluate the current candidate selection with the exact previous protocol. Results remain tied to the checkpoint's original identity even if its presentation name changes later.

Focused implementation evidence: one real small-model compute-worker smoke completed two bounded layouts through compiled policy execution; this checks the path and protocol, not learning quality. The focused Core protocol/persistence check passes: semantic rename identity, changed-seed distinction, durable history and interruption recovery. Its exported named-context protocol produces the identical SHA-256 in Python. Logs: `.local/closed-loop-worker.log`, `.local/closed-loop-storage-native.log` (closed-loop test passed; the concurrent storage fixture is tracked separately), and `.local/closed-loop-fingerprint.log`. No broad model benchmarks, live control or installed application qualification were performed for this increment.
