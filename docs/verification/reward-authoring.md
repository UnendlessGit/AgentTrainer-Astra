# Reward definitions, visual signals and rehearsal

2026-09-11, development source on the M3 Max. This is implemented native reward authoring/rehearsal evidence, not a completed live desktop RL claim.

`RewardProgram` defines bounded signals, all/any predicates, score deltas, rising edges, rates per second, manual feedback, readiness, success/failure and an episode time limit. `RewardEvaluator` is value-owned per episode and does not mutate on rejected input. Readiness establishes baselines only after control release. Numeric-change baselines are per rule, so one rule's outlier bound cannot corrupt another rule sharing its signal. Summation follows definition order for deterministic floating-point behavior. Rate conditions use the left endpoint of the actual decision interval; they are a specified sampled rate integral, not an assertion about unobserved intermediate state changes.

Missing, stale, future, low-confidence or wrongly typed values never become a zero reward. Numeric and edge gaps break their history; reacquisition does not invent a change. An unknown total or outcome remains explicit. Manual feedback requires exact episode/window coverage and contiguous sequence proof from the producer; an empty array is not evidence of zero feedback. The coordinator must finish detector/input-producer barriers before evaluating a window once. The external learner rejects an unresolved window at seal instead of guessing its reward or continuing status.

`VisualRewardDetector` reads owned native BGRA sRGB frames and content-relative, top-left regions. OCR uses Apple's local accurate [Vision text recognizer](https://developer.apple.com/documentation/vision/vnrecognizetextrequest), revision 3, an explicit supported language and no language correction. Number parsing requires one unambiguous value with a configured decimal/grouping convention. Image similarity compares all RGB values after sRGB template-size resampling; it is fixed-region appearance similarity, not translation-invariant object recognition. Templates are hash-addressed, bounded, checked on read and published without overwriting earlier content.

The native editor is available from Reinforcement learning's “Rewards & Episodes” button. It supports immutable saved definitions shared across agent copies, signal/rule/episode editing, drag-to-select regions with keyboard-accessible numeric fields, templates from recorded pixels, and frame/sequence rehearsal. The language picker uses the installed recognizer's supported list. Sequence rehearsal uses the sealed native recording reader and real evaluator, emits unknowns for absent manual feedback, stops at its first terminal condition, supports cancellation, and saves a report containing the exact definition and recording identity. It never posts input or fabricates automatic reset readiness.

## Verification

`swift test --filter Reward` passed 12 meaningful checks: missing/reacquired values, independent delta limits, marker timing/sequence/coverage, readiness/confidence/conflicting outcomes, sampled duration rates/truncation, bounded definition validation, immutable shared catalog ownership, template corruption before publication, explicit numeric conventions, real local OCR of a generated score plus blank-frame unknown, image-region/color/integrity behavior, and a sealed native frame sequence whose image-match edge pays exactly once. The sequence test saves/reloads its complete report and rejects duplicate publication and cancellation. The first report-write test exposed Foundation's fatal rejection of combined `.atomic`/`.withoutOverwriting`; staged synchronization plus exclusive hard-link publication fixed it, and the relevant checks passed afterward.

Initial cold Vision startup while other experimental work was active took about 33 seconds. The later complete 12-test run, including two actual OCR reads, took 0.175 seconds after compilation. These are different process/cache conditions, not a general OCR throughput or deadline guarantee. Detector initialization and asynchronous reward labeling must remain outside the actor's timing-critical path.

`scripts/render_ui.py --output .local/reward-ui-renders-final` exported 72 actual native base views, including the four reward pages in light/dark mode at 1120×760 and 860×580. Direct inspection found and fixed a centered-frame offset that disagreed with drag coordinates and numeric fields whose populated values obscured their labels. Existing native sidebar off-screen rendering limitations remain as documented in ui-rendering.md. Actual keyboard/VoiceOver and live pointer interaction are still separate qualification gates.

Remaining integration includes asynchronous desktop rollout collection, stable surface-role rebinding, explicit manual producer coverage, live detector resource/latency qualification, authored/reset-action execution and the full installed capture/control workflow. The editor does not change the built-in practice environments' reward formulas.
