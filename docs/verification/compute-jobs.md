# Local compute jobs

The worker exposes real asynchronous `checkpoint.create`, `checkpoint.inspect`, `dataset.prepare`, `train.behavioral`, `evaluate.behavioral`, and `train.reinforcement` jobs. `cancel` and `job.status` remain responsive while one dedicated thread owns MLX model, optimizer and dataset state. The separate actor role exposes inference commands; the compute role keeps training ownership isolated. Reinforcement job details and current evidence are recorded in [Reinforcement jobs](reinforcement-jobs.md).

Every asynchronous request has a runID. The acknowledgement returns a jobID before execution can emit progress. `job.progress`, `job.completed`, `job.failed`, and `job.cancelled` preserve the original request/run identity. The output queue coalesces progress while retaining control/terminal messages; an unrecoverable output overflow cancels work and closes the process. No raw frames or arbitrary recorded input are included in progress messages.

Training consumes an immutable recording dataset or an explicitly requested `practice_oracle` verification source. The latter requires `verificationMode=true` and reports its generated provenance. Cancellation after a complete training chunk publishes a resumable checkpoint, including pending gradient accumulation and exact sampler/recurrent state. Destination checkpoints and dataset revisions use exclusive immutable publication; a cancelled job never reports completed training.

The original eight integration tests passed in source and through an isolated PyInstaller-built helper on 2026-09-06. Seventeen source job tests, including real reinforcement collection/update/cancellation/resume, passed on 2026-09-08; frozen reinforcement qualification remains separate. Tests exercise real small-model training, cancellation/resume, falling NLL, evaluation, checkpoint inspection, native recording dataset preparation, malformed requests/transport, progress pressure and a lost progress consumer. The same frozen entry-point tests pass with network access denied and a PATH-only environment without PYTHONPATH. The frozen helper passed strict signature verification and its Python archive contains no Torch/torchvision runtime modules.

This proves the exercised worker entry points; it does not prove the native training UI, production-scale jobs, final installed bundle, arbitrary macOS inference, asynchronous desktop PPO, or final release. Later model changes require rebuilding and repeating the frozen checks.
