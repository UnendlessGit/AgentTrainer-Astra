## Capture and input findings

- Capture enumerates displays and on-screen normal windows, excluding the app's own windows; supports display, window, display region and window region, exact output sizes, cursor choice and up to 240 FPS configuration. `Capture/CaptureService.swift:53–124,187–220`. There is no independent application-source kind in this implementation. Display fallback chooses the first available display when a configured ID is absent; window capture instead fails when the ID disappears. This difference can silently change observation scope. Window scaling uses the first intersecting `NSScreen`, with a final 2× fallback, rather than a recorded transform or frame attachment.
- The explicit complete/started, idle, and blank/suspended/stopped classification is valuable (`Capture/CaptureService.swift:26–39,248–280`). Idle invokes a reuse callback; invalid capture does not become a valid unchanged observation. Capture stop drains its callback queue before writer finalization and can preserve a finalized video despite a stream stop error (`155–184`). Astra should retain those semantics with explicit observation validity and lossless frame references.
- Saved recordings use hardware-required HEVC Main, video-range 4:2:0, configurable bitrate and 1–8-bit quantization; previews/runtime use BGRA (`CaptureService.swift:115–134`; `HEVCWriter.swift:145–198`). This is useful proxy/export functionality but is incompatible with Astra's independently chosen lossless primary learning source. Hardware encoder backpressure drops frames and reports only aggregate counts (`HEVCWriter.swift:204–247`). The final frame is extended to the actual host stop time so static recordings retain duration (`289–320`).
- Input capture uses a listen-only session event tap with a dedicated run loop, one-second startup readiness and 100-ms reconciliation timer (`Capture/InputCaptureService.swift:135–226`). Synthetic events carry a distinct tag and are ignored (`229–247`). Physical HID state, live HUD state and filtered persisted state are separate. Tap timeout recovery immediately reconciles missed transitions; revisions reject a poll made stale by a concurrent event or first-frame seed (`638–727`). These are useful independent test cases for Astra's native helper.
- Legacy input is not a complete raw record: key auto-repeats are discarded (`InputCaptureService.swift:291–295`), Caps Lock becomes an artificial one-nanosecond tap (`441–457`), scroll is normalized/clamped (`271–288,432–439`), hotkey and user-blacklisted keys are removed, and reconciliation adds synthetic logical edges with no separate provenance field. Astra should retain raw source timestamps/events plus clearly marked reconciliations and derive learning labels separately.
- The first-frame seed queries physical state at callback arrival but returns samples timestamped at the earlier capture frame (`InputCaptureService.swift:85–132`). The file writer then clamps any earlier event timestamp to the latest written timestamp (`Storage/InputEventFile.swift:23–51`). These prevent unbalanced/reordered files but can conceal causality changes. Astra's first-observation held state must derive from a timestamped event ledger; represent missing prehistory explicitly and preserve late-arrival source times.
- Shortcut suppression covers the full triggering key/button/modifier lifecycle, preserving unrelated modifiers (`Hotkeys/GlobalHotkeyMonitor.swift:13–89`; `InputCaptureService.swift:765–885`). Carbon registrations reject autorepeat and expose failure status; mouse bindings use local/global monitors. Carry shortcut isolation into Astra without deleting raw recorded evidence.
- Injector control changes and releases are serialized under one lock, including re-enable, live keyboard permission changes, and stop (`Agent/InputInjector.swift:31–81,166–182`). Movement/scroll are gated on prediction freshness, while desired hold sets are reapplied on every accepted call (`83–163`). It supports eight button heads, keyboard allowlists, explicit output permission filtering, region/full-desktop control and relative camera motion with optional recentering. Relative movement remains `mouseMoved` while buttons are held; ordinary movement uses drag event types. Cleanup emits neutral relative movement and restores cursor association (`186–242`). Astra should test these OS effects but keep its timed packet/receipt contract rather than the fixed thresholded vector.
- The injector and reenactor post globally to the HID event tap; their own files do not verify focus, target identity, lease or parent liveness. Their ledgers cannot release on a whole-app crash. Reenactment loads the full event stream, reconstructs trim-start holds, clamps points to the recorded global rectangle, schedules by `ContinuousClock`, and releases on cancellation (`Replay/InputReenactor.swift:16–78,81–166`). Its button path uses the previously tracked cursor rather than the button sample's own position. These establish why Astra's independent helper, authoritative target geometry, deadlines and crash-cleanup evidence remain necessary.

## Storage and lifecycle findings

- A dedicated actor owns a shared recording library and model library; roots can be independently relocated to local/mounted storage while logs remain in support storage (`Storage/WorkspaceStore.swift:4–213`). Relocation stages copies before switching roots and deleting originals; unavailable external volumes produce a clear error (`1713–1728`). Copies are verified by **file count and byte totals**, not byte identity (`1754–1771`). Future Astra relocation/export should verify content hashes and use a durable migration journal with a visible recovery outcome.
- Imports accept native packages, folders, or a portable library with folder/context sidecars. They validate manifests, event count/order/finite values, video duration/dimensions, regular files and safe artifact names, remap collisions and context labels, then stage publication (`WorkspaceStore.swift:378–540,975–1147`). Exports deduplicate selected IDs, require an empty destination and stage a self-contained subset (`548–598`). Import validation reads video metadata rather than every frame; these paths do not establish full media integrity. Astra has no legacy-import requirement, but portable native exports and collision-aware imports are worth retaining for Astra data.
- Fixed 72-byte little-endian input records have a magic/version header, bounded 256-KiB writer buffering, synchronized close, mmap access, ordering/finite validation, and a cheap preview/diagnostics scan (`Storage/InputEventFile.swift:4–104,136–272`). Partial trailing records are rejected as a whole file; there is no block checksum or tail recovery. Write failures are retained and surfaced on finish while later appends are silently ignored. Astra needs prompt failure propagation, exact raw round-trip, a recoverable committed prefix and explicit gap/incomplete-session records.
- Individual manifests use temporary-write/replace; bulk folder/context/import operations keep rollback copies only in memory (`WorkspaceStore.swift:773–931,1958–2010`). Hidden staging directories preserve some deletion failures, but list APIs skip unreadable data or return an empty catalog (`662–681,737–740,795–797,1167–1214`). An interrupted transaction can leave inconsistent multi-file state without a journal. Folder deletion itself mutates recordings one by one before the folder index (`933–950`). Astra should expose unreadable/recoverable entries rather than silently presenting missing data, and distinguish crash-atomic transactions from rollback on thrown errors.
- Context field/value names and IDs are reusable, appear as portable assignment snapshots, support bulk edits, and merge by normalized name while handling ID collisions (`WorkspaceStore.swift:814–940,1792–1932`). Catalog edits rewrite existing recording snapshots. Astra should retain reusable labels while freezing dataset/run revisions; label edits must not mutate an active experiment's semantics.
- Profiles duplicate their entire model tree via staging (`WorkspaceStore.swift:1225–1248`). Reset stages versions and both checkpoint kinds after clearing active-profile references; protected-profile handling is a product feature, not an Astra named-profile requirement (`1252–1293`). Version deletion preserves rollback and bounded autosave pruning protects active/manual versions (`1394–1452`). Astra should retain clear duplicate/fork and retention workflows with immutable checkpoint provenance.
- RL snapshot publication writes its manifest and activates profile progress after checking the weight file exists, then prunes autosaves (`WorkspaceStore.swift:1330–1366`). Version listing validates metadata but not weight-file integrity. Generic version activation restores the BC `Checkpoint` from weight/optimizer/training/RNG sidecars and rolls back on errors (`1457–1572`); it does not restore `RLCheckpoint`. This requires explicit training-origin/resume handling in Astra and the separate ML/RL audit, not a claim that selection always restores the exact resumable training state.
- Logs combine OSLog and rotating JSONL, a bounded in-memory list, recent-report copy, log reveal, and crash-report discovery (`Core/AppLog.swift:21–146`). All OSLog messages/details are marked public and diagnostic reports include app state. Astra should keep useful exportable diagnostics with explicit privacy-conscious field selection and preview; do not collect raw observations or arbitrary user content by default.

### Consequential lifecycle edge cases

1. **Successful source data can be deleted by a later error.** `AppModel.stopRecording` finishes the event stream, stops/finalizes capture, writes a manifest and thumbnail, but its catch removes the whole recording directory (`App/AppModel.swift:683–720`, particularly `719`). An event close error or manifest-write error can therefore destroy otherwise usable visual/input data. DAgger similarly deletes on publication/attachment failure and discards the whole correction when visual drops exceed 5% (`1741–1859`). A cancellation between directory creation and assignment to `recordingDirectory` can also leave an unindexed directory (`606–611`). Astra should preserve a committed prefix and recoverable staging state, report incomplete/invalid intervals, and make disposal a separate user-visible action.
2. **Normal cleanup is not independent crash cleanup.** `panic()` schedules a main-actor task that awaits agent/RL stop before recording/training stop (`App/AppModel.swift:1880`). App termination waits in loops without an overall timeout for every workflow (`App/AgentTrainerApp.swift:102–123`). Input capture joins a run loop with an unbounded `DispatchGroup.wait()` (`Capture/InputCaptureService.swift:199–226`). Generation/revision checks handle many normal asynchronous cancellations, but a blocked main actor, hung operation or process crash can prevent those paths. Keep the helper lease/emergency release contract and reciprocal parent cleanup from ADR 0001; do not claim safety from these normal-stop functions alone.
3. **Panic availability can be lost during editing.** Editors call `suspendGlobalHotkeys`, which stops panic as well as workflow bindings (`App/AppModel.swift:1999`; `UI/Pages.swift:983,1006,1527,1582,2864`). The Settings keybind editor is disabled for ordinary Run/recording but omits RL (`UI/Pages.swift:2411`), so RL can still be active during rebinding. Startup registration results are not checked in `AppModel.init` (`286–287`), whereas later `saveHotkeys` checks and rolls back (`1980–1997`). Astra's emergency path should remain armed independently while editing and all live-control modes must share lifecycle guards.
4. **Visible settings can describe the next session rather than the active one.** Run loads the selected version and freezes capture/safety/mouse settings locally (`App/AppModel.swift:1198–1332`), while Run displays profile fields and leaves many corresponding capture/safety controls editable (`UI/Pages.swift:2073,2134–2200`). Specific settings, such as output permissions and context, have live side effects; others merely persist the next choice. A version and mutable profile can disagree. Astra should show the immutable active run specification and clearly identify live controls. Version selection, checkpoint resume and live policy activation must be separate operations.
5. **Save success is not represented faithfully.** The editor always shows an Autosaved pill (`UI/Pages.swift:355`), but debounced autosave mutates the in-memory profile first and silently ignores validation/persistence errors (`App/AppModel.swift:985–997`). A pending autosave is neither explicitly drained by normal idle termination nor universally awaited before another operation. Use explicit dirty/saving/saved/error states, avoid losing pending edits, and make invalid field errors local and recoverable.
6. **Reenactment protection is incomplete at this layer.** The UI has an arming toggle and mutual-exclusion guard, but no target identity/focus or physical-takeover monitor in the reenactor, no startup countdown, and no independent lease (`UI/LibraryView.swift:299–305`; `App/AppModel.swift:1871–1879`; `Replay/InputReenactor.swift`). Arming is view state, not tied to a recording/target snapshot. Button samples use the previously tracked cursor rather than their own position (`InputReenactor.swift:107–112`). Astra replay must distinguish passive inspection from real control and route real reenactment through the same helper, scope validation and receipts as agents.
7. **Data errors can appear as empty data.** Library summary failures become zero-key/zero-event summaries (`UI/LibraryView.swift:454–469`); unreadable profiles/manifests are omitted by storage lists. This masks corruption and makes an empty-state explanation unreliable. Distinguish absent, unavailable, unreadable, recovering and legitimately empty states. Export/import and model activation should check complete checksummed artifacts, not only file existence or metadata.
8. **No recording resource preflight is visible in the owned path.** Capture/model settings are range-checked, and DAgger's pre-roll is capped at 512 MB before Run (`App/AppModel.swift:1308–1321`), but ordinary recording does not measure write throughput, reserve free disk or display a remaining-duration estimate. Writer errors surface late. Astra's lossless compression/disk preflight and backpressure behavior remain essential; a recording-option-dependent pre-roll failure should not unnecessarily prevent ordinary agent execution.

## UX, accessibility and information quality

The original is a feature-rich studio centered on global workflow pages. Reusing its product lessons does not require keeping its eight-page navigation, custom theme system, terminology or very dense model settings. The main window has a minimum 1180×760 size (`App/AgentTrainerApp.swift:12`); common side panels are fixed at 280/330/380 points and many settings use long horizontal stacks. This is a concrete source-level risk for narrow windows, large text and long names, not a measured layout result. Astra should exercise responsive layouts and keep the agent, selected checkpoint, environment readiness and next step visible.

The HUD gives human/agent/correction ownership cues, shows only keys used, renders ordinary/relative pointer and scroll state, and runs as a nonactivating mouse-transparent panel across Spaces (`UI/InputHUD.swift:5–75,104–143`). The preview worker keeps only the newest pending frame (`78–101`), and the main app pauses decorative motion while inactive or Reduce Motion is on (`UI/RootView.swift:7–28`). Preserve those resource-conscious behaviors. Add active run identity, observation age and explicit ownership/resume state; guard preview completion by run/generation so an old render cannot populate a newly started session. The separate HUD currently forwards only the custom motion preference and lacks the root's Reduce Motion/background gating (`InputHUD.swift:207` approximately; see its final view modifier).

There is some accessibility support: labeled native controls, selected sidebar values, InfoTip accessibility hints and visual-keyboard key labels. Coverage is incomplete: the custom Canvas learning chart has no accessible data table or axis labels, many icon-only actions rely on help text, fixed small HUD text can reach 6.5 points, and keyboard layouts use fixed keycode-to-label mappings (`UI/Pages.swift:1466–1492,1855–2041`; `UI/VisualKeyboard.swift:16–24,59–77`). Test actual VoiceOver, full-keyboard operation, system contrast/text preferences and alternate keyboard layouts. Do not infer accessibility compliance from use of SwiftUI.

Learning curves intentionally render bounded visible suffixes and preserve min/max values during downsampling. They then discard original sample indices and spread selected values uniformly in x; finite filtering also removes gaps (`UI/Pages.swift:1977–2024`). This can distort horizontal timing/step interpretation. Astra should preserve x coordinates and missing-data markers, label axes, provide exact values and exportable tables, and separate held-out validation from a frozen evaluation protocol.

Several product statements are stronger than the evidence: immediate release on the Home screen depends on the same process/main actor; frame-accurate input synchronization coexists with backdated seeds and timestamp clamping; storage copy verification compares counts and total sizes; Diagnostics says release checks are the only network use even though RL hosts a configurable reward server (`UI/Pages.swift:28–29,70,2343`, `Storage/WorkspaceStore.swift:1755`). The input-to-parameter capacity heuristic is presented as Comfortable/Balanced/High/Too high and recommends reduced sensory input despite acknowledging it is only a guide (`UI/Pages.swift:1063–1297`). Astra should display measured readiness, resource and learning evidence instead of inheriting this heuristic or unsupported assurance language.

No explicit evaluation workspace, checkpoint comparison protocol, local OCR/image reward authoring, recorded reward/reset rehearsal, deterministic practice environment, user-ready reset handshake, or agent-specific editable recording selections appears in the owned interface. The retained trim is recording metadata decided at record stop; passive AVPlayer preview loads the untrimmed video directly while reenactment applies trim (`App/AppModel.swift:706–709`; `UI/LibraryView.swift:454–469`; `Replay/InputReenactor.swift:24–53`). Those Astra baseline workflows must be implemented and verified explicitly rather than counted as legacy parity.

## Distribution, updates and audit isolation

`Package.swift` declares one Swift executable, macOS 15 and an exact MLX Swift 0.31.3 dependency; `Package.resolved` pins MLX and Swift Numerics revisions. `build.sh` first invokes Xcode to produce MLX Metal resources, then SwiftPM for the release executable, rejects coverage-instrumented binaries, checks deployment metadata, compiles icon assets, assembles/signs/verifies a complete staged app, swaps the installed bundle with rollback, packages a DMG with an Applications link, verifies it, and emits source/DMG checksums. `test.sh` prepares the required Metal resource for its test bundle. These are valuable resource-packaging and staged-install lessons. They are code paths, not proof that a particular distributed/installed bundle works.

Do not inherit the original build's default installation into `/Applications/AgentTrainer.app`, named icon assets, stable-certificate/keychain discovery, strict sub-10-MB DMG goal, or cleanup of older distribution files (`build.sh:8,35–79,137–160,238–246`). Astra's separately authorized ad-hoc signature, blank icon, complete packaged MLX/Python/native resources, new app path and final DMG specification govern. Its installed copied bundle must be qualified independently; the original build strips and resigns a DMG app that differs from its developer-installed bundle (`build.sh:225–231`).

The original updater checks latest GitHub release on launch, offers confirmation, downloads a size-bounded DMG and SHA256SUMS, verifies hash/bundle/version/designated signature requirement, mounts read-only, stages a copy and launches a shell replacement helper that waits for app exit (`Core/GitHubReleaseUpdater.swift:251–354,455–614`; `App/AppModel.swift:317–383`; `UI/RootView.swift:39–42`). It drains subprocess stdout/stderr concurrently, a useful general subprocess lesson (`GitHubReleaseUpdater.swift:490–517`). Same-release checksum delivery is integrity checking, not an independent publisher trust anchor; after a two-second reopen delay the script removes the old app without a health handshake. Astra has **no automatic update service** by ADR 0001, so do not transplant this subsystem. Keep build/artifact validation and rollback lessons in release tooling only.

An `AGENTTRAINER_WORKSPACE_ROOT` environment override isolates managed training/model/log directories and ignores configured root preferences (`Storage/WorkspaceStore.swift:99–116`; `Core/AppLog.swift:45–48`). It does **not** isolate all preferences or incidental files: workflow/hotkey/preset migration and appearance use `UserDefaults.standard` directly (`App/AppModel.swift:227–289,1980–1997,2213–2217,2446`; `UI/UIAppearance.swift:194–226`), crash discovery uses the actual home directory, and an updater helper writes under `$HOME/Library/Logs` (`AppLog.swift:109–112`; `GitHubReleaseUpdater.swift:550–551`). There is no complete audit-launch isolation flag or skip-update flag in the inspected entry point/owned source. The auditor therefore did not launch the original prebuilt app or inspect its private data. UI conclusions here remain source-based; runtime qualification is a separate decision.

## Baseline reconciliation and required evidence

The source supports keeping ADR 0001's process separation, native timing/geometry, independent held-input cleanup, lossless raw storage, immutable revisions, one model/action contract, explicit evaluation and agent-centered workflows. It does not justify replacing those decisions with the legacy single-process app, fixed action vector, HEVC-only source storage, hidden RL lifecycle or global mutable configuration.

Recommended additions to record in a follow-up decision, without rewriting ADR 0001's independent provenance:

| Proposed addition | Reason and qualification |
|---|---|
| Reusable context labels and optional agent conditioning | Preserve generic user-created categorical fields/values and blank/mixed editing. Dataset/model vocabularies and per-run selections must be versioned; mutable catalog names must not change active tensors. No predefined game-specific fields or privileged reward signals. |
| Recording/environment presets | Freeze all settings, source identity and geometry, controls, folder/labels and selection rules per session. A disappeared source must require deliberate reselection, not fallback to another screen/window. |
| Correction recording with pre-roll | Retain explicit takeover/correction distinction and attach provenance to the originating agent/checkpoint. Pre-roll carries actual executed history and causal observations; only demonstrated correction intervals receive expert labels. Validate resource budget independently from ordinary Run. |
| Portable Astra-native libraries and safe relocation | No legacy format import. Offer collision-aware native import/export, shared nonduplicated recordings, independent storage locations and missing-volume feedback. Use checksums, durable journals, snapshot consistency and visible recovery rather than count/size checks and in-memory rollback alone. |
| Bounded retention and checkpoint forks | Retain named/manual/active checkpoints and let users fork before incompatible changes. Distinguish selected inference version, experiment resume checkpoint and active runtime policy. Make retention policies inspectable. |
| Optional external reward adapter | Retain compatibility with a local loopback rewarder where useful, subordinate to the common environment/reward contract. Freeze schema, episode/run identity, timestamps, sequence/deadline handling and malformed/stale/disconnect semantics. It must not be necessary for fresh-policy RL or ordinary inference. Transport details receive the separate RL audit's review. |
| Source truth plus recovery provenance | Preserve raw repeats/scroll/event timestamps and arrival ordering; add reconciliation, filter, takeover and terminal-release provenance. Compute first-observation state from the event timeline, not later physical reads backdated to a frame. |
| Diagnostic export and operation state | Keep bounded logs, throughput/memory/thermal observations, visible partial-data recovery and explicit saving/errors. Provide privacy-conscious report preview and accessibility tables; report active run identity and actual receipt/deadline faults. |

Release checks motivated by these findings must include: stationary/idle capture and invalid surfaces; mixed-scale and negative-origin displays; missing/reused target IDs and focus changes; tap timeout/revocation and permission attribution in the installed bundle; held controls at first frame and trim boundaries; modifier sides, Caps Lock/Fn, mouse side buttons, repeats, smooth scroll and relative camera cleanup; rapid stop/restart/rebinding during every control mode; helper/parent death and blocked UI; disk-full/partial-tail/manifest failure/corrupt-block recovery; interrupted import/export/relocation/label changes; checkpoint selection versus BC/RL resume; active versus next-run settings; large/long-name libraries; VoiceOver/keyboard/contrast/Reduce Motion; and a copied installed-DMG end-to-end workflow.

No application release gate is satisfied by this inspection. It completes only this auditor's assigned read coverage and provides evidence to the integrated audit and baseline reconciliation.
