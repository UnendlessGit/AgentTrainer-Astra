## Product behavior and workflow

The original implements a separate online PPO engine around the same Policy-v6 actor used for demonstration training and ordinary Run. Its critic and PPO optimizer are private to RL. A profile can start with a fresh random actor, warm-start an existing runnable actor, or resume a compatible combined actor/critic checkpoint. Fresh RL needs no recordings; it also has no authored context vocabulary until an existing version supplies one. Existing-version startup freezes its preprocessing, training/model configuration, cursor rendering, and context schema, while intersecting saved and current channel capabilities. RLE 60–63, 249–279, 330–379, 410–413; App 1428–1449.

RL configuration belongs to an AI profile. The hosted reward endpoint belongs to the whole application. The user configures the RL allowlist/settings in AI Models, selects environment/capture/control settings in Run, and invokes a global shortcut. Normal start/stop is deliberately shortcut-only, default Control–Option–Command–L; there is no equivalent start button. Recording, replay, Run, and RL cannot own live control simultaneously. Offline demonstration training on a different profile may run concurrently; same-profile BC and RL are rejected. Record/Run hotkeys ignore an active RL session, so correction recording is not a direct in-session RL workflow. App 84–121, 134–164, 210–224, 1070–1075, 1392–1417; Domain 1586–1592; README 29–33.

Startup validates Accessibility, profile/action/server configuration, observation memory, and the selected brain; constructs/restores the optimizer; starts the listener and waits for one rewarder; sends `episode_starting`; sleeps for the configured start delay; starts physical-input monitoring; activates the target application where possible; starts ScreenCaptureKit and the action timer; resets rewards and sends `episode_started`. Window activation records an application PID, not a window readiness proof. RLE 227–299, 360–387, 470–538, 1970–1982.

The engine reuses native capture/preprocessing, input injection, safety settings, Game Camera parameters, output permissions, context selection, and preview. Capture runs at the saved model's perception FPS, with queue depth 3 for latest-frame mode and 8 for ordered mode. Latest-frame capture overwrites a bounded slot; ordered mode synchronously waits on the inference queue. Idle capture reuses the last usable image. An independent timer executes predicted input at action FPS. RLE 496–519, 773–838, 1507–1577.

Ordinary Run loads exported actor weights without a reward connection or critic. It reapplies immutable RL capabilities and saved action behavior, samples binary actions, removes continuous exploration noise, then applies the same stabilization. Its random seed also incorporates current uptime, so repeated Runs are not a fixed evaluation protocol. Runtime 267–341, 427–455, 1166–1179, 1211–1245, 1373–1376. This preserves a valuable standalone execution path, while the deliberate mean-only continuous Run mode remains a different policy from stochastic collection and needs its own evaluation.

The hybrid action is a fixed 146-element vector. Independent Bernoulli factors represent binary controls; independent Gaussian latent values become absolute positions through sigmoid or signed camera/scroll values through tanh. The sampler retains latent values for PPO scoring and sums active factor log probabilities, including transform-Jacobian terms. Inactive outputs are zero. RLP 119–169, 192–217; DEVELOPMENT_GUIDE 236.

The filter deterministically changes sampled cursor/camera/scroll values after sampling. The stored `distributionActions` remain the original samples, while `executedActions` contains a predicted, filtered, sanitized control vector. This is a legitimate way to score latent decisions through a deterministic environment transform; it does **not** prove the stored executable vector was actually delivered by the OS. The stateful filter and input firewall must remain part of the environment/dynamics contract. Binary controls have no learned sub-interval tap, release, repeat, or ordering representation. RLP 13–23, 233–326; RLE 987–1035, 1562–1572.

## Observations, rollouts, PPO and episode boundaries

Each observation retains packed current pixels, packed spaced past images, paired past predicted controls, and optional fixed-schema context values. The temporal ring stores selected finite history; missing startup history duplicates the current reduced image with zero controls. The model recomputes a GRU/LSTM across each history window and uses its final output, with no carried episode hidden state. Consequently shuffling whole observations is internally consistent with the original finite-window policy; it is not evidence for Astra's persistent recurrent PPO chunks. RLP 6–23, 797–836; RLE 875–923, 1018–1027; Network 620–641.

At each accepted perception the actor/critic predicts first, then rewards accumulated since the previous drain finalize the previous pending transition. It next checks remote done, episode duration, and step count; a time/step limit may bootstrap from the current pre-reset critic value. A full rollout triggers PPO before another action is sampled. Otherwise the engine stores a pending transition, publishes controls, and increments environment/episode decision counters. RLE 924–1040, 1063–1100.

GAE uses `reward + gamma * nextValue * continuation - oldValue` and a boolean terminal separator. Returns are computed before optional whole-rollout advantage normalization. PPO shuffles stored observations each epoch, recomputes the summed joint log probability, clamps log-ratio to ±20, applies the clipped surrogate and optional clipped value loss, and adds average per-active-action entropy. The critic and actor share visual features and both receive gradients. Dropout and the supervised random temporal-control mask are disabled by `model.train(false)` during both collection and update. RLP 358–410, 585–694, 711–789; Network 624–627, 672–677.

Every update sets `updateInProgress`, clears the prediction/history/filter, and synchronously releases controls. Capture admission is suspended. It sends `training_update_started`, mutates the live actor in place, drains and discards rewards received during the update, counts discarded reward messages, extends the episode's wall-clock deadline by the optimizer duration, sends `training_update_finished`, and re-enables input for a fresh perception. A done received during the update survives as a boolean and triggers an episode boundary. RLE 773–781, 1102–1176.

At ordinary episode boundaries the engine releases controls, sends `episode_finished`, updates if enough rollout data exist, records return/lifetime counters, optionally publishes an actor, and sends `episode_starting`. It waits `interEpisodeDelaySeconds + interEpisodeStartDelaySeconds`, clears reward/history/filter state, and admits the next episode with `episode_started`. There is no environment adapter, local reset action routine, condition wait, manual-ready acknowledgement, or starting-state verification in this path. The external rewarder is implicitly responsible for resetting the environment. RLE 1179–1363.

Short boundary segments are retained until at least four transitions are available. The last transition is forced terminal before carrying a short segment across reset, which prevents GAE leaking across unrelated episodes but throws away time-limit bootstrapping for those segments. A configured final episode or final stop updates even one transition. Session-relative limits/cadences avoid immediately ending a resumed lifetime run. RLE 1208–1219, 1249–1265, 1332–1336; RLD 530–559.

## Reward integration, liveness and reset protocol

The current implementation is a single-client Network-framework WebSocket **server**, not the outbound `ws`/`wss` client described in 2.4.0 release notes. Default URL is `ws://127.0.0.1:47831`; listener starts only for RL. Remote connections are disabled by default. URL validation requires `ws`, an explicit port 1024–65535, no credentials/query/fragment, and loopback unless remote access is enabled. Startup waits up to 15 seconds for the rewarder. Messages are capped at 64 KiB; the listener queues at most 32 outbound messages while disconnected. RLD 192–248; WS 235–335, 338–378, 574–590; `RELEASE_NOTES_2.4.0.md` 10; `RELEASE_NOTES_2.4.5.md` 9–12.

Incoming JSON accepts a finite numeric reward, boolean done, configured episode-finished type, or configured heartbeat. Reward booleans/strings/nonfinite numbers and semantically empty objects are rejected. Default protocol also accepts historical `episode_finished`, `terminated`, and `episode_end` aliases; customizing any names selects exact names. JSON heartbeat refreshes freshness without reward, whereas WebSocket ping/pong only maintain transport and do not refresh the reward clock. Fields/type values are bounded, trimmed, control-free, collision-checked, and frozen at startup. WS 113–152, 492–524; RLD 94–189.

A lock-backed constant-size accumulator keeps Kahan sum, latest value, numeric message count, done flag, last receive time, total received count, and invalid count. No per-reward records survive draining, so individual source timestamps, episode IDs, late arrivals, duplicates, and causal attribution are unavailable. Sum/mean/latest all return zero when no reward was received; a heartbeat can therefore sustain zero-reward transitions during intentionally sparse feedback. WS 14–95. The socket receive callback creates a Task per delivered message but schedules the next receive only after current processing, so the accumulator comment about no per-message task applies to the accumulator rather than the complete socket path. WS 12–13, 476–524.

Outgoing events are episode finished/starting/started and update started/finished; metadata includes episode, ISO wall-clock timestamp, reason, return, steps, and optional next episode. Sends have no application acknowledgement, sequence number, reset nonce, run identifier, or inbound matching check. The synchronous engine wrapper waits at most one second for `send`, whose completion means network content processing rather than remote reset completion. WS 155–181, 338–362; RLE 1765–1808.

Default reward timeout is five seconds; disconnect grace is one second; invalid-message stop threshold is a lifetime cumulative count of 25. Each stop behavior can be disabled; reward/heartbeat timeout may be set zero. Disconnect immediately invalidates controls and queues release; default stops/saves after grace unless reconnected. Optional pause mode resets the causal history and resumes on reconnect/fresh reward while extending the episode timer. Stale/connection pauses finalize pending experience as terminal. Invalid-flood checking and stale-reward detection occur on inference progress, not an independent reward watchdog. RLD 198–206, 234–245; RLE 840–857, 930–953, 1047–1055, 1366–1505.

## Stopping, checkpointing and publication

Stop marks the session stopped, invalidates the latch and disconnect-stop generation, cancels the action timer, drains the action queue, disables/releases input, stops the physical monitor and capture, drains inference, terminalizes pending experience, performs any remaining PPO update, and prepares a runnable actor if updates are unpublished. Otherwise it still refreshes the combined checkpoint. It finally emits an episode-finished reason, stops the server, tears down memory, and reports completion. Capture errors, human input, focus loss, inference staleness, permission changes, and app panic reach this path. RLE 546–669, 671–718, 1524–1572, 2031–2053; App 1880.

The combined checkpoint contains actor/critic weights, AdamW moments/metadata, MLX random state, and JSON with compatibility signature, selected actor identity, lifetime counters, elapsed duration, sampling RNG, reward normalization state, recent returns (capped at 1024), cumulative return, and last metrics. Files are written into a sibling temporary directory and replaced/moved as a unit. Runtime actor publication saves a separate actor-only safetensors file and manifest. The manifest preserves RL origin, allowlist, behavior, cursor inclusion, mouse mode, architecture/preprocessing, context schema, and summary. RLE 33–52, 1233–1242, 1622–1762; RLP 460–470, 792–795; Domain 1253–1345.

Resume checks model marker, a SHA-256 hash of many configuration fields, selected actor ID, bounded counters, and some finite summary values; it then checks presence of the three tensor files. Signature covers model shape/precision/preprocessing/history, channels/restrictions, context schema, mouse mode, action behavior, PPO/reward settings, and seed. It omits source identity/geometry, cursor rendering, perception/action cadence, actual output permissions, context values, Game Camera scale/sensitivity settings, reward definition/producer identity, episode-limit settings, and software/dependency hashes. Several omissions alter the environment or sampling timeline even if tensor shapes agree. RLE 330–379, 1810–1967.

The checkpoint is a learner continuation at a new episode, not a restorable environment episode: pending/retained rollouts, live temporal/filter state, current world state, and individual rewards are absent. The engine starts at `completedEpisodes + 1`, zeroes current return/steps, and resets history. Normal stop's final experience is not added to completed-episode history before snapshotting. RLE 33–52, 418–440, 584–603, 1658–1663.

Storage owns activation and summary updates after writing a version manifest, retains ten autosaves, copies the entire profile directory on duplication, and resets both demonstration and RL checkpoint directories with version artifacts. Commit checks that actor weights exist as a file; it does not validate their hash, finiteness, or loadability. Version manifest validation checks RL metadata and safe leaf artifact names. Store 1225–1292, 1306–1364; Domain 1327–1354.

## Correctness and stability findings

These are source-supported risks and defects; none is presented as a failure reproduced by running the original app.

1. **Live time and reward causality are not represented.** `infer` discards the capture timestamp, records no transition time/duration or execution receipt, and drains rewards only after model prediction. A decision can be published and counted without ever reaching the OS; variable GPU delay changes reward bins while GAE still uses fixed gamma/lambda per transition. Latency measures inference work, and stale action checks age the publication rather than the captured observation. RLE 840, 924–963, 1009–1040, 1545–1552; RLP 13–23, 375–382. Astra's monotonic observation/transition/receipt contract and duration-aware returns are necessary.

2. **Updates assume control can pause while the environment need not.** The engine releases all input and discards intervening rewards, then changes policy and resets temporal state in the same numbered episode. Bootstrap comes from before that uncontrolled gap. A live target may continue moving, lose a round, or accrue consequences during the update; elapsed-time subtraction cannot undo those dynamics. RLE 977–984, 1102–1176. Preserve Astra's immutable actor/learner separation, bounded pending update, continuity measurements, and policy activation only at a confirmed reset.

3. **Reset and outcome semantics are too weak for auditable RL.** Fixed delays and outbound delivery do not confirm environment readiness. Remote done is one boolean; stop, focus/human intervention, capture loss, reward disconnect/staleness, and context changes can be learned as terminal outcomes. Tiny time-limit segments intentionally lose bootstrap when deferred. RLP 21–22; RLE 584–588, 711–716, 940, 1214–1219, 1302–1363, 1452. Astra needs distinct terminated/truncated/aborted outcomes, trusted pre-reset bootstrap, Manual Ready, and validated optional reset routines.

4. **Continuous sample/scoring formulas are inconsistent before any update.** Scalar sampling subtracts `log(max(1e-7, J))`; tensor scoring subtracts `log(J + 1e-7)`. RLP 155–159 versus 624–628. Holding the policy and latent sample fixed at signed latent 8, the formulas alone give a likelihood ratio about **0.81823** instead of 1, before considering Float/Double differences. This illustration was calculated independently from the formulas, without executing original code. Tests only verify sampled bounds/determinism for continuous outputs, while actual PPO update tests and benchmark activate one binary key. RLT 181–219, 686–788, 992–1042; Perf 16–66. Astra must share sampling/scoring primitives and block optimizer admission if the full old-policy joint probability does not agree across masks, tails, and precision modes.

5. **The continuous entropy term supplies no actor exploration gradient.** It is the fixed latent normal entropy determined by configured SD, not entropy of the sigmoid/tanh action distribution. The continuous term is constant with respect to the mean and contains no transform contribution; it cannot discourage saturation. RLP 565–569, 667–680. Astra's bounded categorical arguments avoid this density issue; any future continuous alternative needs an explicit entropy definition and gradient reference checks.

6. **Numerical failure is checked after mutation and does not protect saved state.** The compiled graph updates weights/moments before returning loss/KL scalars; only those pre-update scalar metrics are checked afterward. There is no finite-gradient/norm/parameter/moment guard or rollback in the optimizer. Mixed precision casts model weights back to FP32 each step without retained master weights; norm accumulation uses incoming gradient dtype. A finite loss can still precede corrupted update state, which the stop path may retry/update/save. RLP 686–694, 754–773; Network 1065–1073, 1150–1180. This supports Astra's FP32 master/optimizer state, pre-update finite checks, candidate update validation, and preserved last-known-good checkpoint.

7. **KL stopping occurs after one further mutation and uses clamped tails.** KL is computed from the current forward pass, but the compiled function applies its update before the caller compares it against 1.5×target. It can therefore apply another step even when that forward already exceeded the bound. Log-ratio clamping also changes the surrogate/KL in extreme tails; no raw ratio-tail diagnostics or full-rollout guard appear. RLP 636–647, 681–694, 754–773. Astra should define the guard precisely, evaluate it before accepting the next candidate, and record joint ratio tails.

8. **Incomplete checkpoint files can restore old history with fresh learner weights.** `restoredState` remains selected even when `checkpointFilesAreComplete` is false; the optimizer then warm-starts the active actor or creates a fresh actor/critic while counters, reward statistics, and sampling state come from the incomplete checkpoint. RLE 340–379, 413–417. This is neither exact resume nor a cleanly identified new run. Completeness/integrity validation must accept or reject the checkpoint as a whole, with an explicit warm-start outcome.

9. **Publication is not one crash-atomic transaction across checkpoint, version, and profile.** `prepareSnapshot` changes checkpoint actorVersionID to a new UUID and writes that checkpoint before storage publishes the version manifest/profile. A failure or crash between these steps can leave the old active actor pointing at a checkpoint with a different required actor ID, forcing fallback. File existence is the only actor validation at commit; checkpoint metadata hash is not artifact integrity. RLE 1628–1649, 1815–1827; Store 1344–1356. Astra's immutable artifact manifest, integrity checks, atomic publication pointer, and crash-injection recovery are warranted.

10. **Declared seeding does not isolate fresh model initialization.** Actor and critic modules are constructed before the configured session `RandomState`; module initialization has no scoped seed. Configured seed does control the custom sampler, minibatch shuffle, and later MLX random state, but does not by itself make fresh policies reproducible. RLP 504–527, 731–743; Network 48–136. Astra's three-seed experiments require independent recorded initialization, action, shuffle, and environment RNG streams.

11. **Protocol identity and endpoint validation do not establish trusted causal signals.** The server binds a port, uses local-only access according to the toggle, and accepts every WebSocket request path/origin without authentication; the configured URL host/path do not select a matching listener address/path. Incoming messages carry no required run/episode/sequence identity and cannot reject delayed old-episode rewards. This matters even for a mistaken local rewarder; enabling remote access widens exposure. RLD 209–221; WS 267–315, 113–152. Astra should keep ordinary coordination on inherited local channels and make any optional reward bridge an explicit, versioned adapter with authorization and causal identity.

12. **Readiness and teardown rely on one process and partially checked asynchronous state.** Safety/inference queues and locks are in the app process; no independent actuation lease/helper watchdog appears in the engine. A capture callback already performing prediction can pass its initial guard, then still create a pending transition after a concurrent stop/disconnect, although the timer's guard blocks later posting. Startup enables its engine state before several asynchronous capture/monitor operations and has no startup waiter analogous to Runtime's 257–265. These are race and unexecuted-transition risks requiring installed-app cancellation/fault tests, not established failures from static reading. RLE 859–872, 987–1040, 546–574, 485–529. Astra already specifies independent cleanup, run/generation identities, deadlines, and receipts.

13. **Metrics mix incompatible clocks.** `environmentSteps` counts policy perceptions but snapshot experience duration divides by action FPS. `prepareSnapshot` resets `sessionStartedAt` while runtime frame/action counters continue; average FPS then divides cumulative counts by the latest snapshot interval. Partial final episode returns may not enter completed-episode averages. RLE 1031–1040, 1573–1576, 1615–1616, 1628–1629, 1658–1684. Astra should derive experience duration from transition timestamps and keep separate immutable run, active-control, episode, and optimizer clocks.

14. **Resource admission is useful but is not an aggregate contention budget.** Startup estimates rollout pixels/history/metadata, caps retained rollout at 1 GiB and one-quarter physical RAM, and checks an estimated model-plus-rollout budget against three-quarters RAM. It does not reserve capacity across concurrently allowed BC work and the live target, measure GPU deadlines, or account for all transient minibatch copies/compiled graphs. RLD 429–455; RLE 280–299; RLP 814–835; App 1070–1075, 1403–1407. Astra should retain preflight estimates and add measured aggregate memory/pressure/deadline admission.

## What the tests and release evidence establish

The tests encode useful regressions: default empty allowlist and server validation (RLT 7–62), stochastic binary sampling and permissions (64–179), deterministic bounded continuous sampling/filtering (181–287), session-relative limits and short-rollout admission (289–316), terminal GAE/normalization (318–343), bounded reward aggregation and protocol/custom naming (345–438), actual loopback WebSocket transport at 120 messages/s, reconnect and custom names (440–644), config/migration checks (646–684), finite PPO with changed convolution weights and matching actor/critic reload (686–789), finite single-transition update (791–838), actor warm-start (840–870), manifest metadata/storage reset (872–955), and hotkey migration (957–990).

The core update fixture uses 16×16 grayscale input, zero past frames, FP32, a tiny network, and one allowed key. It verifies parameter change, not improved expected reward or task success. The performance gate similarly repeats one constant observation and the same sampled key action across its retained rollout, with synthetic rewards and no capture/control/environment loop. It measures PPO throughput/memory, not native closed-loop RL. RLT 992–1042; Perf 16–96.

No execution was performed in this audit. The release-note totals, 120-Hz transport result, and approximately 99-sample/s PPO result are historical claims, not newly reproduced evidence. `RELEASE_NOTES_2.4.5.md` 34–38. The read RL test suite does not establish joint ratio-one for continuous/saturated actions, duration-aware GAE, actual OS receipts, reset readiness, no-drop finalization under every asynchronous race, deterministic next-update resume, fault-safe publication, persistent recurrence, or improvement on held-out live tasks. The plan's full workflow and installed-bundle release gates must remain open.

## Retained capabilities and warranted Astra revisions

The original validates the value of a direct no-demonstration RL path, actor interoperability with BC and ordinary Run, explicit action capability selection, independently stored learner state and runnable versions, sparse-reward heartbeats, bounded reward aggregation, useful episode/update diagnostics, session-relative limits, bounded retention, and saving progress on orderly stops. These should remain product capabilities without adopting the original fixed-vector action representation, shortcut-only entry, global endpoint dependency, or pause-during-update assumption.

ADR 0001 already resolves the consequential architectural findings: common environment contracts; explicit causal timing and execution receipts; shared joint action scoring; persistent recurrent chunks; distinct outcomes; duration-aware returns; immutable actor versions; a live actor during learning; reset readiness; FP32 numerical state; integrity-checked checkpoints; local reward authoring/rehearsal; and installed-workflow verification. No evidence here warrants replacing PPO, the proposed action grammar, the GRU baseline, or the actor/learner split.

Record the following additions in a later reconciliation record rather than rewriting the independent ADR's provenance:

1. Make **reward-signal liveness separate from reward magnitude/availability**. Sparse rewards and unknown OCR must be distinct from a dead producer; track no-signal time and producer status without inventing zero observations. Expose orderly stop/recovery behavior. WS 53–55, 60–78; RLE 930–951.
2. Support an **optional external reward adapter** after the local authoring path, with bounded payloads, explicit endpoint scope, immutable protocol version/configuration, run/episode/sequence identity, timestamp mapping, stale/duplicate rejection, and readiness acknowledgement. It should use the same reward/outcome contract as OCR/manual/fixture signals. This retains programmatic environment integration without making WebSocket setup a first-success prerequisite. WS 155–181, 267–315, 574–578.
3. Specify **short rollout and orderly-stop semantics** explicitly: retain valid short segments with correct outcome/bootstrap information, allow a deliberately sized final update, and never label missing or unexecuted samples as on-policy data simply to avoid discarding them. RLE 584–588, 1208–1219, 1332–1336.
4. Specify **three separate recovery outcomes** in the UI/manifest: exact learner resume from a fully valid checkpoint; actor-only warm start with fresh optimizer/critic/RNG; or new policy. Preserve compatibility diagnostics and last-known-good artifacts. RLE 340–379, 531–535, 1810–1967.
5. Extend numerical gates to cover **all active action combinations, saturation/tail probability agreement, entropy gradients, KL admission order, finite candidate optimizer state, and seeded initialization**. Require replayed next-update equality after checkpoint restore and crash injection between artifact and activation publication. RLP 119–169, 624–694, 754–773; RLT 761–775.
6. Keep **raw reward, conditioned reward, task outcomes, interventions, episode length, and policy/control timing** separately visible in recorded diagnostics and evaluation. Saved policy distribution and deliberate deterministic/mean execution alternatives must each have a named evaluation protocol. RLE 1078–1099, 1683–1684; Runtime 1171–1178.

## Additional bounded independent source cross-check

At the model auditor's request, this reviewer also partially read original `Sources/AgentTrainer/Training/TrainingEngine.swift` 170–205, 242–276, 307–365, 415–465, 475–526, 965–987, 1132–1160, 1240–1302, 1340–1358, 1418–1444, 1448–1503, and 1695–1778, plus Network 150–242. These are additional partial reads, not ownership of the full files. Two static integration findings were independently corroborated and sent to that audit:

- With feature reuse enabled and per-sample augmentation disabled, production training still creates N-row identity augmentation parameters and applies them to deduplicated U-current/P-past tensors before expanding observation mappings. Non-singleton U/P dimensions unequal to N cannot broadcast to that shape. TrainingEngine 182–190, 485–512, 1149–1150, 1280–1291, 1427–1434; Network 163–213, 216–222. The disabled augmentation path also clips zero luminance to 1e-4 rather than being a literal identity (Network 200–201). DomainTests 4308–4395 exercises the lower-level deduplicated temporal function without this production augmentation stage.
- The compiled validation closure captures a run-global feature-reuse layout, while correction/rehearsal evaluation calls construct batches with reuse disabled. If ordinary validation selected reuse, the closure reads action/map positions for a different descriptor layout. TrainingEngine 248–260, 317–327, 425–461, 973–981, 1247–1297, 1349–1353, 1474–1482. This demonstrates why independent operator tests cannot stand in for complete workflow verification. Neither finding was reproduced by executing original code; the model audit owns their broader reconciliation.
