# Original learning, dataset, and inference audit

## Scope and provenance

This review followed Astra's independent baseline commit `505ec37` and reads the original AgentTrainer at commit `86387f1a143eaad84c2b24d47cae095f2677da31`. It is an implementation audit, not adoption of the original development guide as Astra requirements. No original source, data, build outputs, tests, or Git state were intentionally changed; no original builds, benchmarks, or tests were executed. Only this Astra report was written by this reviewer.

The original README and release notes describe historical verification. Their numbers are reported claims, not reproduced results. Findings below distinguish direct implementation behavior, source-level defects, and experiments Astra still owes. References use original repository-relative filenames and one-based line numbers; short filenames resolve through the coverage table.

The broad result supports ADR 0001: preserve precise temporal/action contracts, persistent recurrence, immutable dataset/checkpoint provenance, explicit execution receipts, joint action likelihoods, and full installed-workflow evidence. The original contains useful optimization and product lessons, but its component throughput results do not justify replacing those decisions with its much smaller, fixed-window policy.

## End-to-end behavior

### Model and inputs

The default original input is a 640×360 color image, with four 320×180 past images spaced two configured perception ticks apart. At the configured 30 Hz perception rate this is nominally 0.267 seconds of lookback. Actions are labeled at 60 Hz. These are independent user-configurable settings; live dropped perceptions can extend the actual lookback. The model receives neither elapsed time nor image age/validity. (`Domain.swift:428`, `Domain.swift:466`, `Domain.swift:926`; `AgentRuntime.swift:1045`.)

`AgentPolicy` is a randomly initialized Swift MLX CNN. Current/past images share convolutions, and each input gets deterministic X/Y coordinate channels that are deliberately excluded from module reflection and optimizer parameters. The default stack is 32/64/96/128 channels with 7/3/3/3 kernels and 4/2/2/2 strides; each stage uses GroupNorm and SiLU. Attention pooling learns eight spatial score maps, concatenates their weighted features and coordinates with global mean/max features, and projects to 256 values with LayerNorm/SiLU. The legacy flattened option instead has separate current/past dense projections dependent on spatial size. There is no pretrained backbone, full-resolution detail branch, or dense pointing distribution. (`PolicyNetwork.swift:14`, `PolicyNetwork.swift:48`, `PolicyNetwork.swift:143`, `PolicyNetwork.swift:299`, `PolicyNetwork.swift:422`; `Domain.swift:635`.)

The recurrent input is each past visual embedding plus that frame's 146 controls. A single GRU or LSTM of default width 192 starts afresh for each supplied sequence, returns its last state, and concatenates that state with the current visual embedding. The current frame does not update an ongoing recurrent state. Zero past frames substitutes a zero recurrent vector and avoids past-image input allocation. The fused vector optionally receives a recording-level categorical context, then two default dense layers of widths 384/256 with LayerNorm, SiLU, and default 0.1 dropout. Training independently masks the entire control-history half for half of rows. Evaluation disables both dropout and control masking. (`PolicyNetwork.swift:102`, `PolicyNetwork.swift:489`, `PolicyNetwork.swift:620`, `PolicyNetwork.swift:644`.)

The 146 outputs are two absolute cursor coordinates, two relative deltas, eight buttons, two scroll axes, 128 virtual-key slots, and four modifier slots. Absolute coordinates/binaries use sigmoid; relative/scroll use tanh. Shift participates in Keyboard; duplicate Command/Option/Control keyboard slots are suppressed in datasets and runtime. Enabling either mouse movement flag trains both position and delta heads; Run chooses which to execute. Fixed extra heads predict four future action vectors and an action-conditioned visual-embedding delta. They remain parameters even when their losses are disabled, but ordinary inference does not execute them. (`DatasetCache.swift:78`; `PolicyNetwork.swift:120`, `PolicyNetwork.swift:682`, `PolicyNetwork.swift:705`, `PolicyNetwork.swift:755`; `Domain.swift:526`.)

### Preprocessing and dataset derivation

One Metal path handles live BGRA and decoded bi-planar full/video-range YUV, including declared 601/709/2020 YCbCr matrix conversion, fit/fill/stretch, luminance/chroma packing, and 1–8-bit value quantization. Packed storage is always byte-per-value Y and optional subsampled Cb/Cr; lower bit depth reduces value precision, not byte count. MLX expands packed bytes to float32 NHWC Y/Cb/Cr values inside the compiled graph; it does not convert the model input back to RGB. Chroma expansion repeats subsampled values. Fit bars are black but carry no explicit validity mask. The preview reconstructs color from the exact packed model input. (`VisionPreprocessor.swift:110`, `VisionPreprocessor.swift:207`, `VisionPreprocessor.swift:238`, `VisionPreprocessor.swift:298`, `VisionPreprocessor.swift:363`; `Domain.swift:437`.)

Cache identity hashes preprocessing, temporal configuration, action/perception rates, recording selections/timing/geometry/context IDs, and video/event file size plus modification time. Recording display names and folder moves do not change pixel identity. Cache manifests can refresh context display names without repacking. Identity does not hash artifact contents. The cache contains five binary files plus a manifest: current packed perceptions, reduced perceptions, current/past index maps, one aggregate control row per perception interval, and independent action-rate targets. (`DatasetCache.swift:10`, `DatasetCache.swift:198`, `DatasetCache.swift:1358`, `DatasetCache.swift:1477`.)

Construction streams AVAssetReader's native YUV decode through shared Metal current/past submissions and bounded ordered writes. A held frame is packed once and repeated for every configured perception tick until the next frame; each tick still gets a distinct observation index and frame-control interval. A maximum eight pending packing jobs is selected from a nominal 64 MiB packed-output budget. Files are buffered, synchronized, and finalized in a temporary directory before publication. Loading requires mapped files, checks exact byte lengths, schema, shape arithmetic, segment contiguity, causal spacing, and leading sentinels, then applies adaptive VM advice. It does not scan all action values for finiteness or verify content hashes. (`DatasetCache.swift:292`, `DatasetCache.swift:358`, `DatasetCache.swift:1391`, `DatasetCache.swift:1493`, `DatasetCache.swift:1545`, `DatasetCache.swift:1592`, `DatasetCache.swift:1807`.)

For each recording, input state is primed at the usable trim boundary, retaining held controls and pointer position while clearing earlier additive deltas and tap edges. Past-image controls summarize the interval following that past perception. Targets summarize the interval following the current action tick. Unavailable leading past slots duplicate the current reduced image with zero controls, avoiding current-target leakage through the padding itself. DAgger observations may precede the first supervised target. Previous action targets are gathered separately for transition weighting. (`DatasetCache.swift:737`, `DatasetCache.swift:1125`, `DatasetCache.swift:1640`, `DatasetCache.swift:1655`, `DatasetCache.swift:1675`.)

The action reducer retains final pointer position, sums relative and scroll deltas, and marks a binary active if held at the end **or pressed at any time during the interval**. Relative movement is divided by 80 and clipped to ±1; scroll is divided by 20 and clipped to ±1. This retains evidence that a short tap happened, but loses ordered edges, exact duration, repeated taps, repeat events, trajectories, and motion beyond the clip. (`DatasetCache.swift:1730`; `Domain.swift:583`.)

### Training, validation, and checkpoint workflow

Training runs in a detached task with a session random state, dedicated MLX stream, shared mapped-input buffers, and a coarse preflight working-set limit of two-thirds physical memory. It derives key capabilities from the training split. Multiple ordinary recordings are split whole by sample-count/coverage heuristics while retaining every demonstrated binary output in training. All DAgger segments stay in training and at least one ordinary recording is retained when available. A single recording instead receives a contiguous split and a gap intended to make input-history indices disjoint; insufficient disjoint data means no validation. There is no independent test split. (`TrainingEngine.swift:75`, `TrainingEngine.swift:116`, `TrainingEngine.swift:207`, `TrainingEngine.swift:1777`.)

Training orders each row once per epoch using deterministic salience balancing or grouped/locality lanes. These are independent fixed-history examples, not persistent recurrent TBPTT lanes. Deterministic current sequences and repeated past observations may share CNN work within a batch, then gather back to one stochastic recurrent/fusion path per label. Per-row augmentation disables this training reuse so every row gets an independent photometric transform shared across its current, past, and future images. Validation shares deterministic logits where useful. The trainer asynchronously launches Metal and gathers one next batch on CPU before waiting for the completed optimizer graph. (`TrainingEngine.swift:155`, `TrainingEngine.swift:485`, `TrainingEngine.swift:678`, `TrainingEngine.swift:747`, `TrainingEngine.swift:1613`; `DatasetCache.swift:530`; `PolicyNetwork.swift:601`.)

The immediate objective averages enabled head-group losses. Mouse loss averages absolute smooth-L1 and relative smooth-L1; active relative/scroll targets get 8× emphasis. Binary loss combines a training-split negative/positive ratio capped at 1024, zero weight for unseen keyboard/modifier dimensions, 4× press/release emphasis, and normalized focal weights with default gamma 1.5. Correction rows multiply numerator contributions by their weight, normally four, without canceling that emphasis in the denominator. These are deliberately weighted objectives, not calibrated joint packet likelihoods. (`DatasetCache.swift:916`; `PolicyNetwork.swift:834`, `PolicyNetwork.swift:895`, `PolicyNetwork.swift:937`; `Domain.swift:952`.)

Default future action horizons are 0.10/0.25/0.50 seconds, with loss weight 0.05 and inverse horizon-index weights. Future-state prediction uses a 0.25-second horizon, every second action row, and weight 0.025. It regresses a stopped-gradient difference of the same trainable encoder's future/current embeddings, conditioned on the demonstrated current action, with bounded extra emphasis on latent change. This is auxiliary representation learning; it is not a validated world model or planning system. Future data are target-only in the policy forward path. (`Domain.swift:826`, `Domain.swift:856`; `PolicyNetwork.swift:970`, `PolicyNetwork.swift:1011`.)

AdamW maintains float32 moments and explicit bias correction, warmup, cosine restarts or legacy inverse-square-root decay, a validation-driven envelope, and a floor. Parameters themselves are stored in the selected precision, default BF16. The global gradient norm is clipped to one. Returned losses are checked for finiteness after the update. Epoch metrics and presentation histories are bounded; step timing measures the pipelined work and reports MLX memory and thermal state. (`PolicyNetwork.swift:1059`; `TrainingEngine.swift:262`, `TrainingEngine.swift:589`, `TrainingEngine.swift:783`, `TrainingEngine.swift:1512`, `TrainingEngine.swift:2159`.)

Validation uses a fixed bounded subset, up to 8192 rows, prioritizing binary positives, transitions, active movement/scroll, and recording diversity. It reports weighted immediate loss, per-head binary confusion counts, absolute mouse MAE, active delta/scroll MAE, and false continuous actions while idle. Ordinary best-weight selection requires lower weighted loss without a severe sparse-head regression. Correction selection requires at least 0.2% correction-probe improvement with an ordinary loss tolerance of 2% or 0.0005, plus the sparse-head guard. The correction probe is explicitly training data; if no held-out ordinary data exist, the guard is rehearsal, not validation. (`DatasetCache.swift:1021`; `TrainingEngine.swift:211`, `TrainingEngine.swift:379`, `TrainingEngine.swift:931`, `TrainingEngine.swift:1537`, `TrainingEngine.swift:2269`; `Domain.swift:1236`.)

Checkpoint publication stages weights, first/second AdamW moments, optimizer metadata, random state, training cursor/history/config signature, model schema, and optional best weights before replacing the checkpoint directory. Resume matches signature, recording order, and known sampling strategy; otherwise compatible active weights warm-start a fresh optimizer and their baseline is re-scored. Saving the selected best brain intentionally omits optimizer/random/cursor artifacts when they belong to later weights. Autosaves are runnable and bounded, and publication changes the profile's active version. Explicit pause saves and publishes after an optimizer step; `stop()` cancels and returns an error without a final-save guarantee in this engine. Configured step-limit completion can publish a runnable result before finishing the epoch. (`TrainingEngine.swift:13`, `TrainingEngine.swift:113`, `TrainingEngine.swift:880`, `TrainingEngine.swift:1123`, `TrainingEngine.swift:1910`, `TrainingEngine.swift:1942`, `TrainingEngine.swift:1977`, `TrainingEngine.swift:2066`.)

### Runtime and correction recording

Run loads preprocessing, timing, architecture, precision, context vocabulary, and control metadata from a saved version, intersecting executable channels with current disables. It creates the same policy and turns off stochastic training behavior. A bounded latest-frame path coalesces inputs; ordered mode synchronously backpressures capture callbacks. Capture idle reuses the last usable surface. A ring stores every successfully inferred reduced frame and sanitized predicted controls; requested history is selected by completed-inference count, not timestamp. The action timer is independent of perception. A latch supplies held state repeatedly but marks additive motion/scroll fresh only once per published prediction. (`AgentRuntime.swift:267`, `AgentRuntime.swift:311`, `AgentRuntime.swift:867`, `AgentRuntime.swift:992`, `AgentRuntime.swift:1042`, `AgentRuntime.swift:1221`, `AgentRuntime.swift:1299`, `AgentRuntime.swift:1430`.)

The runtime checks finite outputs, focus and physical-input safety, and prediction publication age. Context changes revise the session input, clear prediction/history/filter state, release old controls on the action queue, and discard in-flight inference from the old context. Stop first stops new action admission, drains the action queue and releases controls, then drains capture/inference/DAgger and releases model closures before clearing MLX cache. Startup and duplicate stop requests have explicit cancellation/install/waiter guards. This remains one app process; crash-independent control cleanup is not provided by these routines. (`AgentRuntime.swift:240`, `AgentRuntime.swift:491`, `AgentRuntime.swift:591`, `AgentRuntime.swift:797`, `AgentRuntime.swift:1166`, `AgentRuntime.swift:1312`.)

DAgger is an explicit Record trigger during Run. A separate frozen Record-quality pipeline maintains bounded pre-roll, optionally using a second capture stream when cursor visibility differs. The trigger pauses inference and action admission before recorder construction, buffers early physical events/frames, drains existing queues, releases synthetic holds, and seeds current physical state. The recorder synthesizes pre-roll input events from stored model control rows, releases those synthetic states at the supervision boundary, streams subsequent expert events, and writes hardware HEVC from reconstructed YUV surfaces. Stopping correction clears prediction/history state and resumes resident Run while final video/event publication completes. Startup overflow is an error; later drops are counted, and the domain defines a 5% package acceptance threshold enforced by the wider app flow. (`AgentRuntime.swift:525`, `AgentRuntime.swift:639`, `AgentRuntime.swift:759`, `AgentRuntime.swift:900`; `DAggerRecorder.swift:98`, `DAggerRecorder.swift:158`, `DAggerRecorder.swift:184`, `DAggerRecorder.swift:227`, `DAggerRecorder.swift:310`, `DAggerRecorder.swift:381`; `Domain.swift:912`.)

### Diagnostics and memory

Opt-in activation and feature-channel visualizations share their CNN forward with that inference. Action saliency adds a gradient from a mean of the selected output group's logits back to the final current-frame CNN tensor; it is a Grad-CAM-like diagnostic, not causal proof of decision reasoning. Tensors are spatially sampled to a longest side of 96 before CPU display. CPU image rendering has a single newest pending frame, 640×360 overlays or 600×360 channel grids, and finite/percentile scaling. GPU diagnostic work and CPU tensor extraction still happen before prediction publication; coalesced CPU rendering alone does not guarantee zero latency cost. (`PolicyNetwork.swift:790`; `AgentRuntime.swift:343`, `AgentRuntime.swift:406`, `AgentRuntime.swift:1131`, `AgentRuntime.swift:1183`, `AgentRuntime.swift:1285`; `CNNVisualization.swift:9`, `CNNVisualization.swift:43`.)

The shared-buffer pool validates shape overflow, chooses a smallest adequate reusable allocation, and hands MLX a pointer with an ownership finalizer. Recycling happens only after the array's lifetime; caching is bounded, but in-flight live allocations are separate. Pending Metal preprocessing retains the source pixel buffer/textures until command completion, provides single-consumer access, and recycles on completion or discard. Process-wide MLX limits reserve max(2 GiB, 15% physical memory), cap allocator cache around 0.5–2 GiB, and clear reusable cache after model ownership is released. Other processes, file mappings, ScreenCaptureKit surfaces, Metal input pools, DAgger video surfaces, and app memory are not all included in MLX's active/cache counters. (`MetalArrayBufferPool.swift:35`; `VisionPreprocessor.swift:17`; `MLXMemoryLifecycle.swift:17`.)

## Actionable findings and evidence limits

These are source-level findings, not reproduced failures from executing Original AgentTrainer.

1. **Augmentation-disabled training can feed incompatible batch axes to the production graph.** The reusable branch retains `U` unique current sequences and `P` unique past frames for `N` supervised rows. Nevertheless, `trainingStep` always creates augmentation parameters shaped `[N,1,1,1]` and applies them to current/past inputs. Disabled augmentation returns identity tensors with that same N axis; the transform still performs broadcasting. `U=16,N=32` therefore fails, and a singleton can expand unexpectedly and invalidate later history-map preconditions. Deduplicated future-state images have the same issue when their count differs from N. This is not exercised by the benchmark's separately written deterministic reused graph. Astra should use explicit typed batch contracts and execute production combinations of augmentation on/off, history on/off, reuse on/off, auxiliary on/off, and partial batches. (`TrainingEngine.swift:184`, `TrainingEngine.swift:496`, `TrainingEngine.swift:1149`, `TrainingEngine.swift:1427`; `PolicyNetwork.swift:167`, `PolicyNetwork.swift:194`; `TrainingPerformanceTests.swift:514`, `TrainingPerformanceTests.swift:972`.)

2. **Correction evaluation can use the wrong compiled input layout.** `validationStep` captures `reusesValidationVisionFeatures` when it is created, but correction/rehearsal calls force `makeBatch` into non-reused layout. When ordinary validation selected reuse, temporal action rows move from slot 5 to slot 3, or current-only action rows from slot 2 to slot 1. The compiled decoder still interprets them using the original layout. Astra should have one explicit validated input structure per compiled graph and integration tests through the real correction training entry point. (`TrainingEngine.swift:317`, `TrainingEngine.swift:425`, `TrainingEngine.swift:453`, `TrainingEngine.swift:973`, `TrainingEngine.swift:1247`, `TrainingEngine.swift:1282`, `TrainingEngine.swift:1349`, `TrainingEngine.swift:1474`.)

3. **Auxiliary targets can cross a single-recording train/validation split.** The split gap considers input-history indices only; future action and future-state gathers check recording bounds but do not know split membership. With history disabled the validation gap can be zero, while default future action supervision reaches 0.5 seconds ahead. With default history, the 0.267-second gap is still shorter than the farthest default horizon. Training can therefore use labels or pixels from rows called held-out. Separate whole-session train/validation/test splits and target-aware bounds are required. (`TrainingEngine.swift:1859`; `DatasetCache.swift:998`, `DatasetCache.swift:1196`, `DatasetCache.swift:1237`; `Domain.swift:831`.)

4. **Two dataset initialization choices can move later information backward.** Decode maps the first returned PTS to `trimStart`, regardless of its actual offset; a trim beginning between video samples can make a later frame available early. The initial pointer is the first pointer event anywhere in the recording, even when it lies after the current sample. Ordinary recording seeds can reduce the latter occurrence, but the cache itself does not enforce a causal seed. Preserve true source timestamps, an explicit seed timestamp/validity, and causal floor selection; do not manufacture an observation at a requested time from a later frame. (`DatasetCache.swift:1514`, `DatasetCache.swift:1592`, `DatasetCache.swift:1640`, `DatasetCache.swift:1740`.)

5. **Runtime history and DAgger pre-roll describe predictions, not confirmed execution.** History is appended before the action timer executes. A new latch value can replace a previous prediction without that prediction ever running. The original training frame-control row aggregates a full perception interval, while runtime records one predicted action-interval row, particularly significant at 60 Hz actions versus 30 Hz perceptions. DAgger reads the latest predicted controls after asynchronous preprocessing and writes them at the earlier frame timestamp; later controls can be backdated. Store separate immutable sampled packets, actual scheduler receipts, and authoritative held-state snapshots, all on the same clock. (`AgentRuntime.swift:965`, `AgentRuntime.swift:1221`, `AgentRuntime.swift:1231`, `AgentRuntime.swift:1312`; `DAggerRecorder.swift:158`, `DAggerRecorder.swift:314`; `DatasetCache.swift:1655`.)

6. **Reported freshness and latency exclude observation age.** Scheduling throttles by callback arrival time; temporal selection uses completed-inference count. The stale-output guard measures time since publication, and `latencyMilliseconds` starts immediately before preprocessing, excluding capture/queue delay and later action scheduling. Thus a long inference or old ordered input can be newly published and treated as fresh. Astra's complete observation-to-dispatch percentiles, frame age, expired-packet rejection, and fixed run delay remain required. (`AgentRuntime.swift:997`, `AgentRuntime.swift:1045`, `AgentRuntime.swift:1062`, `AgentRuntime.swift:1248`, `AgentRuntime.swift:1319`, `AgentRuntime.swift:1446`.)

7. **Reduced precision lacks master weights and complete finite-state checks.** Every update starts from the already rounded parameter, converts it to float32, updates with float32 moments, then rounds back. There is no retained float32 master parameter. The norm squares/sums gradients in their existing dtype, and losses/weights are cast to model dtype. Small warmup updates can disappear in BF16; float16 norms/reductions can overflow even when losses are finite. The trainer checks pre-update losses, not gradients, moments, or updated weights. Astra should implement the ADR's FP32 master/loss/log-probability/norm path, finite gradient/state validation, and reject or roll back an invalid update before advancing checkpoint state. (`PolicyNetwork.swift:51`, `PolicyNetwork.swift:136`, `PolicyNetwork.swift:844`, `PolicyNetwork.swift:1160`, `PolicyNetwork.swift:1179`; `TrainingEngine.swift:783`.)

8. **Weighted/focal aggregate validation is not a calibrated likelihood or deployment score.** Positive balancing up to 1024×, transition emphasis, output masking, focal reweighting, and representative oversampling change calibration and the evaluation distribution. Loss normalization is per head per batch, then evaluation averages those scalar ratios weighted only by row count; regrouping heterogeneous rows can change the reported aggregate. A lower score does not establish fewer false presses, better timed releases, precise pointing, or closed-loop task success. Keep unweighted interval NLL, raw event metrics, complete-session evaluation protocols, and frozen checkpoint comparisons. Treat correction fit as fit to intervention data. (`DatasetCache.swift:921`, `DatasetCache.swift:1021`; `PolicyNetwork.swift:895`, `PolicyNetwork.swift:950`; `TrainingEngine.swift:1498`, `TrainingEngine.swift:1537`.)

9. **Original interval labels cannot express Astra's control contract.** Two taps and one tap within a tick can share the same binary label; press-release order and actual timing disappear; high-rate motion is summed and clipped. The inclusive final action loop also creates an endpoint row whose interval can be zero duration. The original action-rate option does not itself make the policy produce independent decisions at that rate. Preserve raw events and adopt the already selected timed packet/trajectory canonicalizer, rejecting incompatible intervals rather than silently saturating. (`DatasetCache.swift:1684`, `DatasetCache.swift:1756`, `DatasetCache.swift:1785`; `AgentRuntime.swift:1299`, `AgentRuntime.swift:1430`.)

10. **Cache/checkpoint identity and recovery need stronger integrity.** File size/mtime identity can accept changed content that preserves those metadata. Loader checks shape/length but not pixel/action content hashes or finite target arrays. Checkpoint restore verifies moment names/shapes and random-state shape/dtype, but not a hash manifest, full finite state, optimizer step versus training cursor consistency, or all cursor bounds. Cache publication deletes an old cache directory before moving the new one. Staging is useful, but does not by itself prove crash durability/recovery. Keep Astra's content-derived revisions, checksummed atomic publication, corruption tests, explicit resume compatibility, and immutable run specification. (`DatasetCache.swift:41`, `DatasetCache.swift:358`, `DatasetCache.swift:1465`; `PolicyNetwork.swift:1248`; `TrainingEngine.swift:21`, `TrainingEngine.swift:1942`, `TrainingEngine.swift:2079`.)

11. **Correction recording imposes lossy and timing-dependent reconstruction.** Its pre-roll is reconstructed from packed Y/Cb/Cr and predicted control summaries, then encoded as HEVC; it is not the original pixel/input stream. Trigger-time physical seeds are taken after queue drains but given the earlier trigger time. Drops below a global 5% threshold can still coincide with the most important correction. Astra should retain lossless source frames/raw events, explicit gaps and provenance, and exclude only demonstrably invalid supervised windows without falsifying the source. (`DAggerRecorder.swift:147`, `DAggerRecorder.swift:310`, `DAggerRecorder.swift:381`; `AgentRuntime.swift:643`, `AgentRuntime.swift:700`; `Domain.swift:912`.)

12. **Diagnostics and memory measurements need end-to-end qualification.** CPU renderer coalescing is a good design, but saliency adds differentiated GPU work before actuation. MLX cache bounds do not bound capture-owned surfaces, pooled buffers, mapped pages, DAgger encoding, target-app memory, or simultaneous actor/learner work. The nominal 64 MiB cache-packing cap still allows at least one oversized job and counts packed outputs rather than retained full-resolution decoder surfaces. Astra should preflight and measure aggregate live resources under capture, recording, diagnostics, and actor/learner contention. (`AgentRuntime.swift:1131`; `VisionPreprocessor.swift:17`; `DatasetCache.swift:1545`; `MLXMemoryLifecycle.swift:17`; `MetalArrayBufferPool.swift:106`.)

## What the assigned performance tests actually establish

The BC benchmark builds synthetic packed image/control arrays, constructs three separate deterministic optimizer graphs, warms them, alternates their timing order, and compares immediate-loss trajectories. It prints maximum parameter deltas but does not assert a parameter-delta limit. Its “validation” comparison uses the same synthetic arrays that the models trained on, comparing two graph forms at the same weights; it is numerical equivalence, not held-out generalization. Its “inference” path uses the training batch shape and does not include live capture, action dispatch, deadlines, permissions, or closed-loop behavior. (`TrainingPerformanceTests.swift:173`, `TrainingPerformanceTests.swift:229`, `TrainingPerformanceTests.swift:290`, `TrainingPerformanceTests.swift:454`, `TrainingPerformanceTests.swift:571`, `TrainingPerformanceTests.swift:597`, `TrainingPerformanceTests.swift:625`, `TrainingPerformanceTests.swift:699`.)

A separate full-objective benchmark tests per-row photometric transforms and both auxiliaries with synthetic future labels copied from present labels and future images copied from current images. Its hand-written graph uses expanded fixed shapes; it does not invoke `TrainingEngine.start`, cache construction, the production `makeBatch`/`expandBatch` layout, correction selection, checkpoint publication, or resume. It asserts finite terminal losses, augmentation overhead ≤3× reused-core cost plus 2 ms, auxiliary overhead ≤2× augmented-immediate cost plus 2 ms, and a cache cap. These are useful bounded workload checks, but cannot detect the production shape bugs above or establish that auxiliary learning generalizes. (`TrainingPerformanceTests.swift:831`, `TrainingPerformanceTests.swift:849`, `TrainingPerformanceTests.swift:865`, `TrainingPerformanceTests.swift:972`, `TrainingPerformanceTests.swift:1052`.)

Sustained windows print throughput retention, active/cache memory, and thermal state. The implemented sustained assertion bounds cache memory; it does not assert a retention threshold or require nominal thermal state. Historical notes report nominal/retention observations, which should remain distinguishable from automatic gates. (`TrainingPerformanceTests.swift:747`; `RELEASE_NOTES_2.4.5.md:37`.)

The PPO performance test repeats one constant observation and the same sampled action across a fabricated rollout, runs an update, and checks finite summary losses/entropy, 1–8 optimizer steps, throughput >0.5 samples/s, active memory <75% physical, and noncritical thermal state. It does not demonstrate environmental learning. The DAgger benchmark sends sixty constant 1280×720 frames through the recorder and requires sixty encoded frames, zero drops, and ≥30 fps. It does not exercise live capture, high-rate human input, correction timing, asynchronous startup, or complete correction training. ## Reconciliation with Astra's independent baseline

Keep the baseline's persistent two-layer GRU, detail-aware pretrained visual experiment, dense pointing, causal action packets, session splits, native timing, independent control helper, versioned execution receipts, and aggregate memory/deadline gates. No inspected original evidence measures these alternatives sufficiently to justify reversing them. In particular, short-window CNN/GRU component equivalence is not a delayed-memory, fine-pointing, generalization, or interactive latency comparison.

Useful capabilities to carry forward in independent form:

- Exact model-input preview, optional bounded visual diagnostics, and visible distinction between processing rate, successful dispatch rate, and dropped/invalid data.
- Generic user-authored categorical task context with stable IDs, immutable per-model vocabulary, explicit blank semantics, and a live-change boundary. This is a product capability to reconcile with Astra's model contract, not a requirement to copy raw one-hot fusion or allow unobserved categories silently.
- Explicit correction capture with useful pre-roll, a clear expert-supervision boundary, normal-library ownership, source policy provenance, and correction-improvement plus ordinary-regression checks. Use execution receipts and retained raw data, not synthesized history.
- Separate newest runnable/checkpoint selection, exact optimizer resume versus weights-only warm start, and re-scoring the selected checkpoint when the dataset/evaluation protocol changes.
- Direct native YUV ingestion, shared current/detail preprocessing work, packed deterministic caches, ownership-safe bounded buffers, CPU/GPU overlap, and reuse of identical deterministic encoder work **within the current training graph**. Do not cache trainable embeddings across parameter updates.
- Per-operation recall, false actions, release/timing/pointing measures, raw confusion counts, bounded chart histories, and resource diagnostics. Preserve ordinary test distributions separately from stratified diagnostic probes.

Add concrete implementation verification prompted by this audit: real production entry points across conditional batch layouts; every auxiliary's split membership; deliberately irregular/late/trimmed frames and absent pointer seeds; multiple press/release/repeat edges per interval; action receipts when predictions are skipped; pause/cancel/final save distinctions; nonfinite gradients and post-update state; corrupted caches/checkpoints; and diagnostics/learner contention in installed live workflows. These strengthen existing gates and do not replace the required three-seed architecture/cadence/hybrid experiments or complete application release evidence.
