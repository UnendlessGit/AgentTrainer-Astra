# Artifact identity and storage roots

A workflow freezes one native `ArtifactStorageLayout`. Models and recordings may use independently selected directories. Catalog documents, datasets, jobs, desktop collections, feedback revisions, reviewed experience, reward assets and claim files remain under the catalog root. Python continues to receive explicit absolute runtime paths; those paths are locations, not new artifact identities.

## Current path inventory

| Artifact | Persistent identity and references | Relocation behavior |
| --- | --- | --- |
| Checkpoint | UUID directory, manifest ID, parent/dataset UUIDs, hashed relative tensor/state files | Copy bytes unchanged and resolve its UUID under the current models root. Parameter names in frozen/optimizer state are model-tree paths, not filesystem paths. |
| BC training state | Dataset UUID; episode UUIDs and sampler position; optimizer, RNG, recurrence and pending accumulated gradients | Retain the exact dataset revision and configuration. No model or recording root is embedded. |
| Practice/external PPO state | Environment/model signatures, policy UUID, contexts, optimizer/RNG; external actor cursor and consumed rollout UUIDs | No model/recording paths are embedded. Fresh physical reset remains required, independently of relocation. |
| Dataset schemas1–3 | Dataset UUID, recording UUIDs and manifest digests, selected ranges/contexts, episode IDs, index digest, relative source shard references | Dataset stays under the catalog root; supply the current recordings root at runtime. Do not rebuild it merely because sources moved. |
| Recording/correction | Recording UUID and relative frame/index/correction members; correction source checkpoint/run IDs | Copy the complete package, including recovery indexes, static-source proofs and correction sidecars. Original data timestamps, metadata and checksums do not change. |
| Retrospective original/derived experience | Immutable binding `continuationSource.sourcePath`; derived `reviewSource.path`; fragment-batch `fragments[].path`, all authenticated with digests | These are absolute persistent paths. Their roots stay fixed in this feature. Rewriting them would alter hashes and, for bindings, trajectory identity. |
| Pending feedback | Source/revision/draft/reviewed-package paths and original native boundary result, plus checkpoint UUID/signature | Experience paths stay fixed. Current `PendingFeedbackWorkflow`, `PendingReviewBoundary` and `FeedbackSourceReader` contain no saved model `policyPath`; model opening occurs later through the learner's checkpoint UUID resolver and verified worker loader. |
| Collector journals | Original requests include absolute output/ring paths | Preserve historical journal bytes. Sealed pixel replay uses package-relative frame files, never historical mapped-ring locations. |
| Admission claims | Adjacent `.consumed-<rolloutID>.json` and `.boundary-<collectionID>.json`; checkpoint-boundary claim schema1 also records an absolute checkpoint `destination` | Remain with fixed experience roots. Never invent or copy a missing admission claim as proof of consumption. Completed claims are not reused for a new collection. |
| Native saved run configuration | Original dataset/checkpoint-related runtime paths may be absolute | Preserve the original file. Build an in-memory runtime payload using its stable IDs and the workflow's frozen layout. |

## Resolution contract

For a catalog with layout `(catalogRoot, modelsRoot, recordingsRoot)`, resolve checkpoint UUID `C` to `modelsRoot/C` and dataset UUID `D` to `catalogRoot/Datasets/D`. A recorded dataset receives `recordingRoot: recordingsRoot`. Recording lookup uses its unchanged UUID package name, including the native `.astrarecord` suffix. Existing worker request fields and artifact schemas remain unchanged.

A BC resume obtains `D` from the verified checkpoint's `datasetID`, uses the original frozen dataset and training settings, and changes only runtime locations. The worker checks checkpoint/tensor integrity, dataset identity, recording manifest fingerprints and original frame checksums. The trainer checks that saved dataset identity and configuration match before restoring sampler, recurrent, optimizer or accumulated-gradient state. Import must preserve artifact UUIDs; a conflicting UUID with different bytes cannot be silently renamed into an exact-resume artifact.

A model-only export may preserve weights and complete optimizer state, but BC resume additionally needs its exact dataset, all referenced recording packages and original native run configuration/catalog provenance. An export advertising complete resume must carry that dependency closure. An unfinished feedback source is a distinct workflow artifact, not part of an ordinary model package; its source files and consumption/boundary claims cannot be reconstructed from a model checkpoint.

Storage switching requires idle workflow owners so an active reader or output publication cannot change roots midway. Old checkpoint-boundary claims retain their original destination string; a future feature that retries the same incomplete boundary publication after moving its model destination must authenticate an explicit old/new destination alias or introduce a versioned UUID destination in new claims. It must not edit the old claim or manufacture a replacement. This does not affect ordinary resume from an already published checkpoint.

Moving the catalog/experience roots themselves is a separate migration: use a digest-bound location resolver for recursive source/fragment references, compare continuation identities by verified UUID+manifest hash rather than raw path text, and keep original manifest/journal bytes intact. This broader migration is unnecessary for independent model/recording roots.

## Focused evidence

`python/tests/test_storage_relocation.py` passes using a real compute worker and generated recordings. It saves BC after one chunk with pending accumulated gradients, resumes a baseline, moves both artifact roots independently, reloads the original checkpoint state exactly, and resumes through the existing worker protocol. Final weights, optimizer/RNG, counters and sampler state match; source, dataset, checkpoint and saved configuration bytes remain unchanged. Result: one check passed in 0.82s (`.local/storage-relocation-python.log`). This exercises directory relocation, not removable-volume disconnects or native import UI.

A second focused handoff verifies the actual native archive closure. `scripts/prepare_artifact_resume_fixture.py` uses the built `AstraFixture` recording producer and a 114,831-parameter numerical-test policy to save one genuine paused BC accumulation. The opt-in Core test `artifactArchivePreservesRealCheckpointDatasetAndResumeConfiguration` (`ASTRA_ARTIFACT_RESUME_FIXTURE`) exports, imports and re-exports the checkpoint, original dataset, native recording and run configuration. `scripts/verify_artifact_resume_fixture.py` then resumes the imported checkpoint through a real worker and compares against continuation of the untouched original. It completed four decisions and two optimizer updates with changed weights, exact integer/RNG state and maximum floating-point difference 1.49e-8; source configuration bytes stayed unchanged and the worker exited 0. Private reports live under `.local/artifact-resume-fixture-20260923`. This is format and resume evidence, not production-model learning evidence.

One opt-in native render check (`ASTRA_ARTIFACT_RENDER_DIR`, `renderArtifactTransferAndStorageSettings`) renders populated export selections and storage settings in light/dark mode using an isolated generated library and the existing owned-view renderer. Four base images and two scrolled settings images were inspected; headings, checked items, long names/paths and export Cancel/Preview buttons fit. No file panels opened and no artifacts were copied. Evidence: `.local/artifact-ui-renders/manifest.json` and `.local/artifact-ui-renders.log` (one check, 1.748s).
