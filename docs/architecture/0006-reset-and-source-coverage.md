# Reset plans and source coverage

Reset control belongs to the environment coordinator and remains outside policy episodes. A reset has its own control run UUID, distinct from the next policy episode UUID, and retains the selected environment, process instance and geometry. The previous actor and controller must join cleanup before reset preparation. Only the actual scoped driver may acquire a new control lease; the reset runner does not create a second input backend.

An absent `RewardProgram.resetPlan` means explicit Manual Ready. An authored version-1 plan contains at most 64 ordered packet, pause or condition-wait steps. Packets use the existing timed-command contract, at most 64 commands and 1,000 ms; pause/wait budgets, overall timeout and 1–3 attempts are bounded. There are no arbitrary scripts, loops or target switches. Required reset capabilities derive from the authored commands independently of the policy's learned action vocabulary. Authored reset requires an explicit final starting predicate; elapsed episode time cannot prove a reset condition.

Packet admission is insufficient: execution must have the correct reset/packet/sequence identity and a complete, correctly timed terminal receipt. Retry is limited to an explicitly configured condition timeout after confirmed cleanup; ambiguous action failure, physical takeover and cancellation do not retry. Deadlines close admission and cancel pending operation waits independently of UI work. Every operation and owned release still joins before completion; timeout never turns pending cleanup into success.

Readiness uses fresh source evidence after the last action and final release barrier. `RewardSourceCoverage` binds a source observation UUID and the complete surface descriptor to original event/observation timestamps, coverage-through time and evidence availability. A frame covers its original source time. Only explicit producer verification that the same pixels and geometry remained unchanged can extend coverage. Silence, a newer wall-clock poll, or an unchanged window identifier cannot do so.

`RewardReadingCoverage` maps a signal to that source evidence. Its signal definition, surface, original timestamps and `SignalReading.sourceObservationID` must agree. Evidence from another surface cannot refresh the signal. Missing, stale, future, low-confidence or unavailable signals retain unknown semantics. Raw timestamps are never rewritten to make a cached reading appear new.

`RewardEvaluator.resolveSnapshot` produces an immutable snapshot tied to the exact reward definition and episode. Readiness and baseline reset consume this same validated value; the next actual actor cutoff must also have source evidence at or after confirmed readiness. Existing callers without explicit coverage retain their previous source-age behavior. Saved reward definitions remain immutable catalog revisions, and old definitions without a reset plan remain readable.

The native environment orchestration owns reset/episode handoff. `NativeResetDriver` binds an already-owned observation producer to a fresh `NativeControlSession`; its [lifecycle contract and evidence](../verification/native-control-session.md) separate packet admission, terminal receipts, acknowledged disarm and joined guardian cleanup. Permission-free runner fixtures and owned-view renders qualify state-machine behavior and authoring layout; actual target effects, privacy attribution and installed-app reset rehearsal remain distinct release evidence.
