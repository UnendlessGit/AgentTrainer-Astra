# Manual feedback without target or policy input leakage

Status: proposed September 19, 2026. This is a design review, not an implemented input channel. No event suppression, new permissions or device access was added for this review.

## Decision

Provide useful manual reward annotation on ordinary Mac hardware after a joined episode. Keep its retrospective provenance explicit. Separately offer an optional isolated live-feedback device after that path passes ownership and input-isolation qualification. Do not advertise ordinary global keyboard shortcuts as universally isolated live feedback.

Astra's existing `PhysicalInputMonitor` is a passive annotated-session event tap that returns every ordinary event unchanged. `AstraControl` treats physical input as takeover; the emergency shortcut is separate. A passive tap cannot prevent an event reaching the target. Even an active CG event filter is insufficient as a universal isolation contract for arbitrary environments that read raw HID state. Apple's documentation distinguishes [passive listeners and active filters](https://developer.apple.com/documentation/coregraphics/cgeventtapoptions). Native AppKit buttons, modifier chords, menu shortcuts and a floating feedback palette also change focus, pointer state or captured desktop pixels during a live episode. Exempting them broadly from takeover would weaken the existing control guarantee.

The current reward contract is deliberately causal: `ManualRewardMarker` belongs to the half-open decision interval containing its event timestamp and must have been observed by that interval's end. `ManualRewardCoverage` proves the complete ordered marker stream for that exact interval. An empty marker list is not proof of zero feedback. The first actor observation accepts no preceding marker interval. These live contracts should remain unchanged.

## Ordinary Mac workflow: review after release

After a natural episode boundary or explicit user Stop, finish the actual in-flight actor/control reconciliation, join all control posting/guardian ownership and manual producers, and stop admitting policy observations before showing review controls. Preserve original receipts, interventions and invalid suffixes. A manual rating must never convert an unverified or partly executed packet into clean experience.

Show an ordinary native review sheet with the episode's retained frames, a scrubber and readable action intervals. Positive/negative actions create annotations targeted to selected original intervals; a separate episode-level rating is an explicit alternative, with an explicitly chosen credit rule. Do not add global keyboard shortcuts. Ordinary local review controls operate only while the app owns focus and agent controls are released. The actor may remain resident under a learning pause. Hide review UI and require a new physical readiness/reset proof before the next episode; review screenshots, app activation and review inputs never become policy observations.

A new immutable annotation record should include:

- annotation ID, episode ID, original packet/observation IDs and exact target interval;
- immutable source artifact digest, policy/checkpoint identity and reward-program revision;
- authoring sequence, actual `annotationObservedNanos` and clock-domain/session identity;
- rule ID and finite label/count, or explicit manual signal/outcome type;
- whether it is interval feedback, an episode rating, a correction or a superseding revision;
- an explicit review-completion record identifying which intervals/rules the user reviewed.

`annotationObservedNanos` will normally be later than the target interval. Preserve that fact. Never backdate it into `ManualRewardMarker.eventNanos`, manufacture live coverage, or feed the label into the actor's observation/context/action history. Timing belongs to both the original behavior interval and the later human judgment; neither replaces the other.

A derived reward revision resolves the annotations against the exact frozen trajectory and reward definition. Unreviewed intervals/rules remain unknown. Zero requires explicit review completion for the covered interval set; closing the window or receiving no clicks cannot mean zero. If an episode-level scalar is used, name and persist its credit rule (for example terminal reward on the last fully eligible interval), rather than silently spreading it across every action. Revised annotations produce a new derived artifact; already sealed trajectories and earlier learning inputs remain immutable.

For PPO, stage a complete behavior trajectory while its manual reward revision is pending. Train only after a valid immutable reward revision and the ordinary physical/outcome/bootstrap eligibility checks exist. The behavior policy, recurrent anchors, original categorical likelihoods, RNG and executed-prefix evidence remain unchanged. Receiving a reward later is normal; allowing an unreviewed label to masquerade as an observed action-time feature is not. A human terminal classification needs its own explicit targeted-boundary semantics. It cannot supply a missing pre-reset value, erase an intervention or invent a valid final observation.

This requires a separate annotation/derived-reward schema and collector/learner admission, not a special case in the current live marker validator. A practical first increment is interval positive/negative annotation with explicit review completion. Arbitrary retrospective text/numeric state trajectories and subjective terminal classification can follow with separately defined semantics. The tradeoff is that learning waits for review, but ordinary Mac users gain usable feedback without weaker physical takeover or extra hardware/privacy requirements.

## Optional live feedback: isolated input producer

The strongest local native candidate is an explicitly selected, dedicated USB feedback device with a narrowly defined report format, opened exclusively. Apple documents that [seize-device access prevents the system and other clients from receiving that device's events](https://developer.apple.com/documentation/iokit/1556660-anonymous/kiohidoptionstypeseizedevice), obtained through [IOHIDDeviceOpen](https://developer.apple.com/documentation/iokit/1588670-iohiddeviceopen). This is a candidate to qualify, not a claim that Astra currently provides it.

Prefer a dedicated vendor-defined, non-keyboard/non-pointer device. Do not seize the Mac's primary keyboard, trackpad, mouse, or a generic game controller that the target uses. Composite devices require ownership of every event-producing interface or refusal to start. Device identity includes the actual connected registry instance and report descriptor; replacement, removal or ownership loss breaks the producer generation. Device button presses create reward messages only. They never become `RawInputEvent`, model control features, action commands, desktop notifications or reactive feedback pixels. All ordinary Mac keyboard/pointer input retains physical takeover, and the existing emergency stop remains active without a feedback exemption.

The producer needs a bounded serial owner, independent of rendering/MLX, with an explicit per-episode generation and marker sequence. Debounce/button-up rules create one marker per deliberate press; repeats do not multiply reward. The chosen timing rule should be receipt-time feedback: timestamp the semantic marker when the serial producer accepts it. Preserve any hardware source time separately for latency audit, not as a backdated reward event. This avoids claiming that a late hardware callback was available at a previously sealed cutoff.

For each `DesktopManualObservation`, the owner emits `DesktopManualSeal` only after ordering all accepted marker work relative to that cutoff. A marker received after the cutoff belongs to a later interval even if the hardware timestamp is older. Seal the exact half-open interval, with contiguous marker sequence and last-sequence proof. First-observation output has no preceding interval or markers. Silence is covered only while the exclusive device stream remains healthy and the producer can prove its ordered boundary; failure/overflow yields unknown coverage and a stop, not zero reward.

Manual state signals require their own explicit value/validity policy. A latched value is not automatically a freshly observed value; do not silently refresh `SignalReading.observedNanos` every decision. Start with discrete live markers unless a signal's refresh/expiration behavior is specified and tested.

On Stop, close ingress, settle accepted observation/seal work, join HID callbacks/queue delivery and report the actual final boundary before episode evidence finishes. A timeout alone is not a producer join. Keep device acquisition outside reset/actor action capabilities. Process death, permission loss, sleep and unplug invalidate coverage immediately; guardian/control cleanup remains independent. Before releasing a keyboard-like interface, neutralize ownership only through actual release evidence rather than injecting compensating synthetic keys. This complexity is another reason to prefer a non-keyboard dedicated device and keep post-episode annotation as the ordinary-Mac path.

## Qualification and unresolved gates

The first software increment should test annotation provenance, source digest/interval binding, explicit zero versus unknown, immutable revisions, no label-as-feature leakage, and PPO admission with unchanged behavior evidence. UI review must begin only after controls/capture admission are joined; next reset must exclude review activity.

Any live device increment must then prove event isolation in a normal target and an owned raw-HID/state-query fixture, ordinary-keyboard/pointer takeover, emergency stop, exact callback ordering and late delivery, held-button/repeat handling, queue overflow, unplug/replacement, denied/revoked access, helper/UI crashes and sleep. Test composite interfaces and failure-time release explicitly. Do not use synthetic success or a healthy-process demo as universal isolation proof. Keep live feedback unavailable when isolation/coverage cannot be established; present the post-episode workflow instead.

No event suppression or extra privacy flow is necessary for the proposed ordinary-Mac review workflow. Device access and its actual macOS permission behavior remain a separate optional qualification gate.

## First contract implementation

The first interval-feedback contract is implemented in `AstraCore/RetrospectiveFeedback.swift`, `FeedbackArtifactStore.swift`, and the CPU-only `astra.retrospective_feedback` reader. Live marker types and existing collector/learner code are unchanged. Review UI, collector production of the pending-review projection and PPO admission of derived rewards are still separate increments.

The source is a digest-bound `FeedbackTrajectoryMetadata` projection with status `awaiting_manual_review`. It records the original collection/trajectory digest, run/clock/session, checkpoint/policy signature, complete reward-program digest, joined boundary and exact eligible intervals. Native derives its bounded manual-rule projection from the full validated definition. Python matches every projected manual rule ID/kind/signed amount to the original program under that hash, while unrelated visual/reset validation stays with the authenticated native producer. `executed` and source-validated `semanticBoundaryPrefix` intervals are supported; the latter requires a semantic endpoint. Truncated intervals preserve their original same-episode pre-reset bootstrap identity, cutoff and finite value. Aborted/audited packages, failed/rejected/unexecuted rows and incomplete bootstrap are not promoted. The assembler remains responsible for constructing this projection from actual physics/evidence; hashing a reviewer-supplied eligibility claim would not be valid integration.

Each annotation targets the full episode/observation/packet/start/end identity and a frozen `manualMarker` rule. Its positive integer count multiplies that rule's existing signed amount. Review completion lists explicit packet/rule pairs. Duplicate identities/pairs, bad sequence/counts, altered targets, unsupported rules and annotations without a completed review are rejected. An explicitly reviewed pair without labels resolves to zero; an unreviewed pair has no count/value. `manualReward` is present only when every manual-marker rule for that interval is reviewed, and covers manual components only. Other reward components, observations, policy inputs, likelihoods, recurrent state, execution/outcome and bootstrap remain unchanged.

Authoring records carry their actual session, clock, monotonic observation time and wall-time audit. A shared clock requires authoring at/after the joined source boundary. Different clocks require different sessions and wall time at/after source closure; unrelated monotonic counters are never compared. Mixed-session correction histories retain original provenance. A reused annotation/review ID cannot change content; corrections get new IDs and an immutable parent revision reference. New correction records must follow the parent publication provenance; unchanged carried records keep their original authoring times.

A revision is a complete snapshot in a new `<revision-uuid>.json` file. Native publication writes a private staging file, synchronizes it, atomically links without replacement, and synchronizes the directory. Loading requires the externally retained expected SHA-256, a verified source/program and, for a correction, its loaded verified parent. It checks regular-file/no-symlink/size limits and re-derives every stored reward. Revisions never overwrite one another; closing the review or failing publication cannot silently complete review coverage.

Bounds are explicit: at most 65,536 eligible intervals, 262,144 interval/rule pairs, 65,536 annotations, 4,096 review-completion records, 4,096 counts per pair, 1 MiB program metadata and 128 MiB revision/source JSON. The interval×manual-rule product and total covered-pair count are both bounded. Larger collections require an explicitly bounded source partition or a separately reviewed limit change, not dropped labels.

Focused verification covers source/artifact tampering, rule/count/target errors, reviewed zero versus unknown, authoring clocks, immutable correction lineage, symlinks, atomic no-overwrite publication, semantic-boundary prefix/bootstrap preservation, and absence of actor-feature rewriting. A Swift-written artifact is independently loaded/re-derived by Python with no MLX import. Exact final counts and paths are recorded in `verification/retrospective-feedback.md`.
