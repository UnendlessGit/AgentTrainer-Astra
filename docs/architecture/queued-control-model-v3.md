# Queued-control neural input — model schema 3

Schema 3 is an explicit opt-in. Schema 2 remains the default and retains its exact configuration serialization, signature, parameter names/count and observation tensor path. Its default signature remains `c90055feaea46483be73f4cd5a48f1dd71867d9ad496ba6ae908b8a83ec94ff3`, with 34,638,639 parameters. A schema-2 policy does not acquire queue awareness by loading new application code.

The new `ObservationBatch.queued_control` is a `QueuedControlBatch`. Its packet dimension is always 64; command capacity is the model's existing 16/32/64 maximum. Live packet counts do not create new compilation shapes. `model/queue_layout.py` is the authoritative versioned index map:

| Tensor | Shape after B,T | Meaning |
|---|---|---|
| categorical | 64,C,7 · int32 | operation, key, button, source role, committed progress status, original motion-anchor operation/source |
| command_features | 64,C,26 · float32 | semantic coordinates/deltas, scheduling time, retained original anchor, observed completion/post timing and emitted relative deltas |
| command_mask | 64,C · bool | complete command prefix, including an empty prefix for a real empty packet |
| packet_features | 64,11 · float32 | admission/start/end timing, duration/count and admission/terminal changes since the acknowledged observation |
| packet_status | 64 · int32 | outstanding, executed, cancelled or late |
| packet_mask | 64 · bool | complete prefix in original packet order |
| available | scalar bool | explicit complete authority, independently of packet presence |

UUIDs, raw packet/lifecycle sequence numbers and absolute clock magnitudes authenticate/order the source only; none enter the network. Pointing x/y are the original normalized semantic coordinates, never past sampled cell indices. Deltas use unclipped binary scaling by 4096 plus signed log magnitude divided by ln(32769). Timing uses integer timestamp subtraction before conversion to seconds: a clipped ±4-second linear feature and signed log preserve both near scheduling detail and longer age. Completion fraction uses the actual committed sample count divided by the interpolation-v1 planned sample count, never elapsed time. Original preceding motion anchors survive intervening key/button commands. Known due-but-unposted commands remain pending.

The builder `data.queued_controls.prepare_queued_controls(feedback, surfaces, config, cutoff_nanos=…, known_empty=False)` invokes the strict raw feedback validator and validates category ranges, finite values and prefix masks before neural allocation. It creates no queue from current samples or shifted teacher labels. Schema-3 unavailable and independently proven known-empty inputs both have inactive residuals; their availability/provenance remains distinct in data. Schema 2 returns no new tensor. Batching and slicing preserve already validated prefixes.

The command encoder uses small categorical embeddings, a projection/LayerNorm/GELU and a 64-wide GRU, batching independent packet rows together. A second projection/LayerNorm/GELU and 128-wide GRU reduce the ordered packet summaries plus header/status features. Prefix gather ignores trailing padding. Zero-command packets still pass their real lifetime/header through the packet encoder. The final bias-free 128→existing-hidden projection starts at zero and is added after the old temporal input projection, before its existing normalization. Existing persistent GRUs, action/value heads, release masks and all 178 actual-control features remain unchanged.

Presence, availability and observation-valid masks keep the inactive residual exactly zero even after its weights learn. This is not a learned missing-state bias. The zero output projection initially blocks gradients into the new encoder; once that projection updates, encoder gradients flow. Widths are internal configuration fields `queued_command_width` (64) and `queued_packet_width` (128), serialized only for schema 3. Nondefault values are rejected for schema 2 instead of being silently hidden from its signature.

At the production hidden width of 512, the branch adds exactly **208,360 parameters** (~0.60%). Fixed input tensors occupy ~0.133 MiB per decision at C16 (~17 MiB for B2×T64), or ~0.523 MiB per decision at C64, before encoder activations. These are layout counts, not measured total runtime memory or latency. Visual microbatching, visual checkpointing and staged visual VJPs explicitly omit queue arrays. The temporal VJP retains them once and differentiates the new branch together with the existing temporal path.

Five focused numerical checks pass across `.local/queued-control-model-tests.log` and `.local/queued-control-staged-gradient.log`: old schema/signature/count parity; exact copied-weight zero-residual temporal/value parity; typed motion anchor/progress and ID exclusion; prefix rejection; projection-then-encoder gradients; inactive/empty-packet distinction; temporal slicing/reset/padding; and full-policy versus staged PPO-gradient parity with a learned nonzero residual. Separate transport ownership checks cover real practice/native/archive evidence. These checks do not establish queued-action competence or resolve the independent passive-cue learning result. Runtime deadline measurements, meaningful delayed-action learning and installed physical qualification remain separate gates.

The implemented `checkpoint.addQueuedControl` job creates a new schema-3 checkpoint identity/signature, copies every old parameter exactly and retains the new zero-output branch. It records source identity/tensor checksum provenance, starts at step zero and stores no optimizer/sampler/recurrent state. The real worker conversion check verifies copied tensors, zero output weights, new identity/signature, unchanged original files, early cancellation and rejection of a second conversion (`python/tests/test_checkpoint_queue_upgrade.py`, `.local/queued-checkpoint-upgrade.log`). Saved policies keep their architecture. Fresh policy settings expose an initially disabled “Queued action memory” choice; Manage Checkpoints offers an explicit separate copy with new-learning-state explanation and joined Stop support. No selected-checkpoint training or resume silently converts architecture.


The first [matched production warm-actor measurement](../verification/queued-control-latency.md) found a2.04ms median increment (+3.43%), with exact sampled outputs and RNG at the zero-residual start. Capture/IPC and learned queue behavior remain outside that measurement.
