# Explicit correction recordings

The operator explicitly chooses **Record Correction**. An active run first stops and joins its controls; a stopped run must already have confirmed cleanup. Only then does Astra start a new physical demonstration, with its own capture stream, raw event sequence and initial reconciliation. Physical takeover alone never starts recording. Resuming the agent is a separate explicit action.

The run retains complete owned observation groups for at most two seconds, 256 observations and 256 MiB of source pixels. Eviction removes whole groups, preserving ordered surface roles. This history remains in memory until a correction is requested. The new recording binds an immutable `correction/prelude.json` by SHA-256 in its manifest. That document identifies the source run/checkpoint/policy signature, original contexts, request/join/supervision times and original actor inputs. Independently checksummed frame blocks live in `correction/frames.astraframes`; repeated immutable frames may share a block.

The current stop/restart handoff does **not** prove continuous input coverage. Therefore `continuityProven` must be false, the prelude is review-only, and expert training starts a new recurrent sequence. A Boolean cannot opt into unsupported recurrent continuity. This is a useful correction of the state where the agent stopped; it is not seamless online imitation or a claim that policy-generated actions were expert demonstrations.

Python validates the sidecar, original observation order/contexts, per-source causal coverage, archive bounds and block checksums. Dataset preparation applies the supervision gate to every correction selection: whole-source selection begins at or after the gate; explicit earlier intervals are rejected. Agent-origin events inside expert coverage are rejected. The immutable dataset records the source checkpoint identity, source contexts, gate and `preRollUse: review_only`; reopening verifies these against the original recording. Ordinary recordings and their loss behavior are unchanged. `RecordingReader.correction_pixels` exposes the separately retained lead-up for review, never as a label source.

Three focused generated-data checks cover gate enforcement, fresh recurrence, preserved provenance, original-frame review, explicit earlier-range rejection, archive tampering, rejection of asserted continuity and rejection of agent activity inside expert coverage. The native Core fixture also exported an LZFSE correction package which Python opened and decoded byte-for-byte (16 × 16 × 4 original pixels, 21 expert frames, zero input events). This is archive interoperability, not a BC training claim. Logs: `.local/correction-native-export.log` and `.local/correction-native-python-read.log`. No live privacy/control qualification is implied.

A future continuous correction mode must first record complete source and input coverage through the handoff. Its training path would require a separate supervision mask while leaving observations valid for recurrence; prefix-only chunks must not cause optimizer or weight-decay updates. That unexercisable path is deliberately absent from the current implementation.
